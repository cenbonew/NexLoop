## 4. 关键路径与近期顺序

按切片排，不按任务排。A 类由调度员直接做，B 类每一步都要负责人确认。

1. **合入在途工作**（A 类）：NX-031 切片 3、NX-032 切片 4、NX-034 第二部分、NX-036 文档交付物（下一轮集成）→ relay 卡死修复、回复结果不明时先对账、API 部署模式与就绪检查（进行中）。
2. **C4-low 本机重跑**（A 类，relay 修复合入后）：切片 3 的重跑已确认死信清零、兜底回复跑通；排空被 relay 卡死缺陷挡住，派发 p95 8.29 s 超过 2 s（容量问题，并入 D-a）。
3. **CI 车道 1000 客户整轮**（A 类，约 4 小时，持 CI 锁，安排在夜间窗口）：含 C4-ci 格与“CI 同机影响报告”，产出 AT-060 结论。
4. **负责人容量决定**（决定）：若 C4 仍不达标，在“降低部署前提（修订 ADR-022 §4、doctor 上限、部署说明）”与“另开优化任务”之间选择。
5. **NX-032 切片 4 容器模拟**（A 类，CI 主机）：AT-058 探测脚本预演、Valkey 服务端 TLS 负例。只算模拟证据。
6. **NX-032 切片 5 真实双机部署**（B 类，按运行手册步骤 0–9 逐步确认）：首次只放合成租户，`REAL_DISPATCH_ENABLED=false`；从三处发起 AT-058 外部探测。
7. **NX-033 主机步骤与切换**（B 类）：建用户与仓库、hook、防火墙、隔离探测、断连演练，然后切换到合并控制器推进 main。
8. **NX-034 服务器侧**（B 类）：首次真实镜像构建与 load 后 digest 核对、签名清单、部署侧校验。
9. **NX-035 部署切片与首次真实恢复演练**（B 类）。
10. **NX-036 公开发布门槛**：全历史审计经负责人确认、安全联系人填写、public-preflight 通过。
11. **NX-037 受控真实闭环验收**：进入条件见 §8。
12. **首个公开 tag 与 GitHub Release**（B 类）。

## 5. 资源与窗口

CI 主机就是规划中的 APP_HOST。下列占用互斥，同一时间只做一项，由调度员持 CI 锁：

| 占用 | 时长 | 说明 |
|---|---|---|
| 全量 CI | 每轮约 33–47 分钟 | 同一时间只跑一轮；每轮集成都要跑 |
| 1000 客户整轮 | 约 4 小时 | 夜间窗口；锁内还要再起一轮全量 CI（C4-ci） |
| NX-032 切片 4 容器模拟 | 待实测 | CI 用户的 rootless Docker |
| NX-032 切片 5 及之后的主机步骤 | 负责人逐步执行 | 部署后 APP_HOST 成为受控运行环境 |

开发机：pytest 最多 3 个并行进程，不跑全量；真实 Pi 测试串行。开发机到 APP_HOST 有一条有线直连（主用）和一条无线链路（备用）。

**待定**：真实部署之后，CI 车道和压测车道是否继续与运行环境同机，需要在 NX-032 切片 5 之前由负责人决定（见 §6）。

- **进度口径**：只报三组数（任务、验收、阶段出口），不合成一个百分比。验收证据分三级：本地（开发机或 CI 主机上的合成环境）、模拟（CI 主机上的容器模拟）、真实（两机部署或真实渠道）。只有满足验收 expected 的证据才能记 passed；S5 的验收只认真实证据。AT-060 按 NX-031 设计，全部格跑完才判定。
- **合并**：开发线不推送、不改 planning；调度员把多条线合成一个集成分支，CI 前在本地跑定向测试与 `scripts/check_publication.py`，在 CI 主机跑一轮全量 CI；失败集须为基线子集，新失败须在同一检出上串行复跑取证，首次失败如实记录。合入后更新 planning、CHANGELOG，跑 `prepush-scan` 后推送并读回。
- **迁移编号**：开发线用临时编号，合并时按合入顺序重新编号（文件名、catalog、`versions.lock.json` 的 bootstrap_revision）；已发布迁移的校验和不改；测试里不写死迁移号。
- **文档**：每次合入后，调度员给文档线发更新单，文档线据此更新 `docs/ARCHITECTURE.md` 和 README。任务状态以 planning 为准，`docs/ARCHITECTURE.md` §6 只做摘要并链接到本文。
- **证据写法**：CI 证据的 ref 用 `ci:lane/runs/<run-id>`；被后续证据取代的说明不删除，由新证据写明“取代哪一条”。
- **上游维护**：vendored EIOS 内核的上游安全修复手工挑选合入；Pi 版本与 Pi 本地 SQLite 例外按 ADR 管理。
