## 1. 目标与范围

v0.1 完成定义第 6 条要求“一个受控真实模型和一次真实交付动作完成”（14 §6）。NX-037 在已部署的两机环境上，用**一个真实租户、一种真实交互渠道、一次真实交付动作、一个受控真实模型**跑通真实闭环，并汇总 S1–S5 全部验收与 v0.1 发布证据包。

| 范围 | 内容 |
|---|---|
| 真实租户 | 一个，独立初始化，与合成 demo 租户和测试数据完全分开（11 §9 D4） |
| 真实交互渠道 | 一种（选型见 D1） |
| 真实交付动作 | 至少一次经受治理 Action、真实 provider 派发、可查询对账的外部效应（选型见 D1） |
| 受控真实模型 | 一个模型档案，≥20 条受控交互，报告模型、工具、平台时间与费用（14 §4；参数见 D2、D7） |
| 汇总 | S1–S5 验收状态、v0.1 发布证据包（14 §7）、已知限制台账（§5） |

**不在范围内**：多租户真实运营、第三方渠道的批量接入、真实优惠发放渠道、S6/S7。

**缺凭据的处理**：真实渠道或真实模型的凭据未就绪时，相关验收记 `blocked`，其他工作继续；**不得**把版本标为“完成真实运营验收”（14 §6，ROADMAP §1）。

### 3.1 受控交互的停止条件

任一条件触发即停止受控交互，并按 [SECURITY.md](../../SECURITY.md) 的处置流程处理：

- 累计费用达到 `<MODEL_COST_CAP>`，或单次 Run 费用超过 `<RUN_COST_CAP>`；
- 出现任何跨租户读取、未授权外发、拒绝联系被忽略、或结果不明的效应被重发；
- 告警规则中的 critical 告警触发；
- 渠道或模型 Provider 返回无法解释的错误率超过 `<ERROR_RATE_STOP>`；
- 负责人随时叫停。

## 4. 需要负责人决定的事项（D 项）

### D1 真实交互渠道与交付动作

- **现状**：唯一已实现的交互渠道是原生 WebChat；外发效应通过 `HttpEffectProvider`（`POST /v1/effects`、`GET /v1/effects/<intent_id>`，`Idempotency-Key` 为 intent ID，见 [CONNECTORS.md](../CONNECTORS.md) §3）调用一个固定来源的服务端点；没有第三方消息渠道连接器。
- **推荐**：交互渠道用**原生 WebChat**（已实现、无第三方依赖）；真实交付动作用一个**企业自有、支持幂等与按 intent 查询的服务端点**，按 `HttpEffectProvider` 协议适配（`nexloop.service.request` 一类的服务交付，声明为非触达客户的 effect 类别或按触达处理，视动作而定）。
- **代价**：不验证第三方渠道（短信、IM、邮件）；“真实交付”取决于企业端点能否提供幂等与查询，若不能，结果不明时只能人工核对。
- **替代**：接入一个第三方消息渠道作为交互渠道——需要新的入站连接器、签名与顺序证据（NX-051 只用合成渠道验证过）和员工回复的“接管 Run”方式，范围显著扩大，不建议放进 v0.1。

### D2 真实模型与 embedding

- **现状**：Agent Host 的可信模型档案只接受 `deepseek` / `deepseek-flash`（`openai-completions` API，`maxTokens` 4096）；embedding 由 `EMBEDDING_*` 配置，维度固定 1024（ADR-020 §5）。
- **推荐**：模型保持 `deepseek-flash`（无需改代码）；embedding 沿用 ADR-019 已配置的 profile；凭据只以私有文件交付（`MODEL_CREDENTIALS_FILE`、`EMBEDDING_CREDENTIALS_FILE`），stage 拒绝环境变量；费用上限设为参数：累计 `<MODEL_COST_CAP>`、单 Run `<RUN_COST_CAP>`、租户月度模型预算 `<TENANT_MODEL_BUDGET>`（NX-022 预算账本）。
- **代价**：只验证一个模型 Provider；换 Provider 需改可信档案与 allowlist（A 类）并重新做出站隔离核对。
- **待负责人给出**：三个费用上限的实际值、凭据交付方式。

### D3 外部数据发送策略

- **现状**：发给模型的只有上下文包 v6（逐来源授权、受限属性组不开放、假设与审核中的 Claim 不进正式区）和工具结果；embedding 请求发送用于召回的文本（13 §5 要求记录“模型出境/外发政策”）。
- **推荐**：NX-037 期间，受控交互的“消费者”由负责人指定的**知情内部人员**扮演（真实租户、真实渠道、真实模型，但不是外部客户），因此首次外发的数据不含外部客户的个人信息；记录 Provider、地区与数据用途；附件与图片不外发（当前也不解析）；真实外部客户的接入另行决定。
- **代价**：交互样本不代表真实客户的表达分布；真实客户接入前还要再做一次外发政策确认。
- **替代**：直接用少量同意参与的外部客户——需要书面同意与删除承诺，不建议作为首次。

### D4 Agent Host 出站隔离（ROADMAP D-c）

- **现状**：stage Compose 示例中 Agent Host 与 API、各 Worker 共用一个网络命名空间（`network_mode: service:app-net`），内部链路都走 127.0.0.1；NX-032 §3.1 要求 Agent Host 出站只允许模型 Provider allowlist 与本机 guard，§3.2 给出的示例规则按 UID 匹配。共用命名空间时，放行模型 Provider 的规则对整个命名空间生效（NX-032 实现说明“未完成项”）。
- **推荐（候选 A）**：Agent Host 放进**独立网络命名空间**，只能到达模型 Provider allowlist 与 guard；guard 与 Host 之间的 loopback TLS 证书补上新地址的 SAN；API 与 Runtime Worker 到 Host 的内部地址相应改为该命名空间的地址。
- **代价**：Compose 与证书模板改动（A 类，NX-032 后续切片）；新地址的 TLS 负例与 AT-058 探测要重做；内部链路多一跳。
- **候选 B**：保持共用命名空间，用防火墙按 UID 匹配 Agent Host 进程的出站。**【待确认】** 在容器共用网络命名空间时，宿主机规则能否按容器内进程 UID 可靠匹配，需要在 CI 主机上实测；若不可靠则不能采用。
- **候选 C**：所有出站经一个只放行 allowlist 的出站代理。代价是新增常驻组件与其凭据管理。

### D5 第二维护者演练（ROADMAP D-f）

- **推荐**：由负责人指定一位第二维护者，在一次性环境（不是运行环境）中只按公开文档执行一次“发布 + 恢复”：[OPERATIONS.md](../OPERATIONS.md)、[NX-032 部署运行手册](NX-032-deploy-runbook.md)、NX-034 发布工具、NX-035 恢复流程；记录每一处需要口头解释的偏差，作为手册修订输入；演练记录作为 v0.1 完成定义第 8 条的证据，并为它新增一个验收项（目前没有验收项承载）。
- **代价**：需要一位能接触一次性环境的人员；演练暴露的手册缺口可能推迟 v0.1。
- **待负责人给出**：第二维护者人选、演练环境。

### D6 首个公开 tag 的顺序（ROADMAP D-d）

- **推荐**：NX-036 公开门槛（含全历史审计与安全联系人）通过后，先发 `v0.1.0-rc.<n>`，发布说明写明“未完成真实运营验收”；NX-037 全部完成后再打 `v0.1.0`。
- **代价**：rc 也要过完整公开门槛（`public-preflight` 九步与负责人确认）；会比 `v0.1.0` 早暴露版本化的接口。
- **替代**：NX-037 完成后直接打 `v0.1.0`——外部更晚拿到可安装版本，但只需过一次门槛。

### D7 受控交互计划的参数

- **推荐**：样本数 `<SAMPLE_COUNT>` ≥ 20（14 §4 下限）；覆盖至少：普通咨询回复、触发一次真实交付动作、一次拒绝联系后的受限回复（ADR-023 §2.6）、一次人工接管与交还、一次结果不明后的查询对账；费用上限见 D2；停止条件见 §3.1；只报告分布，不对小样本做稳定 p95 承诺（14 §4）。
- **待负责人给出**：样本数、执行窗口、`<ERROR_RATE_STOP>`。

### D8 无承载工作的归属（ROADMAP D-e）

ROADMAP §8 第二张表中的各项（工作台优惠发放页面、删除后无身份联系键的重新导入拒绝与撤销入口、租户 ID 规范化等）需要逐项决定：立为 v0.1 任务，还是列入 §5 的 v0.1 已知限制。推荐：租户 ID 规范化与“重新导入拒绝联系”立为 NX-037 之前的任务（涉及数据正确性与联系权利）；优惠发放页面列为已知限制（HTTP 入口已有）。
