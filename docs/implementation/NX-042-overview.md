## 2. 孪生的生命周期

1. **定义**：`nexloop-consumer-twin/1`，必填 schema、twin_id、hypotheses、parameters、generator_version。每条假设的 kind 固定为 `hypothesis`；每个行为是一个区间（`low`、`high`）加 `coverage` 和所依据的假设。字段集合精确校验，带消息正文或 consumer_id 的定义被拒（T1）。
2. **发布（未校准）**：`nexloop.consumer_twin.publish`。版本号由服务端分配；同一请求重放得到同一版本，同一请求改了定义被拒。新版本一律是“已发布、未校准”，附带的 `calibration_report_ref` 只作参照（T1、D7）。版本行与事件只能追加。
3. **校准**：`nexloop.consumer_twin.calibrate`（T5）：
   - 只用 T4 的 real 聚合（D2）；
   - 1–3 个互不重叠的窗口，每个 28、56 或 84 天，必须在版本发布之后开始、并且已经结束；每个窗口前有等长的参照窗口，参照窗口中出现过的消费者不进入校准窗口；
   - 单元 =（行为、窗口、分组），每组至少 30 个消费者；每个窗口最多 8 个单元，**多窗口合并后至少 20 个单元**才给结论；
   - 结论：至少 20 个单元且 |覆盖率 − 名义值| ≤ 0.10（80% 区间即 70%–90%，D3）为 `passed`，否则 `failed`；不足 20 个单元为 `insufficient_sample`；含不可校准的行为为 `not_calibratable`。Brier 分数只作参照。
   - 报告冻结，同一请求重放返回原结果，不写第二份。
4. **校准事件**：只有 `passed` 与 `failed` 写入校准事件；触发器要求有一份版本、结论、定义 digest 都一致的冻结报告。
5. **可被 NX-043 选用**：`runtime.nexloop_consumer_twin_selectable` 只在版本已发布、未作废、最新校准事件为 `passed` 时为真。抽样记录的是抽样当时的校准状态快照，NX-043 选用时要重新读取当前状态。
6. **作废**：`nexloop.consumer_twin.retire`，追加 `retired` 事件并写原因；作废后不可选用，不可撤销。

时间上：发布后至少 28 天才能第一次校准；按每窗口最多 8 个单元，要凑够 20 个单元通常需要约 84 天的窗口。

## 3. 区间输出（D4）

- 每个行为输出 `low`、`high`、`coverage` 和一个布尔的 `simulated_outcome`；区间内抽到的概率既不存储也不返回。
- **区间最小宽度 0.01**（`high − low ≥ 0.01`，调度员定的实现参数），`low = high` 被拒。
- 未校准的版本也可以在模拟世界中抽样，但输出带有“未校准”的状态快照，不能被 NX-043 选用。

## 4. 可擦除文本（D5，`93d68198`）

- 描述与每条假设的陈述存在旁表 `control.nexloop_consumer_twin_texts` 中，冻结的版本行只保存 `sha256:<hex>`，所以擦除不改变定义 digest。
- `nexloop.consumer_twin.erase_text`：负责人专属、只在 real、留审计、按请求重放；把正文置空，记录执行人、时间、原因和请求。重复擦除返回 `already_erased`；删除或改写正文与 hash 被拒。
- 擦除后读取定义时，该文本为 null；决策参数不受影响。文本写入前仍先过“像真实内容”的检查。

## 5. 端口接入与来源标记（T3，`93d68198`）

- 三个入口：`authz.nexloop_twin_bind`、`nexloop_twin_observe`、`nexloop_twin_act`，只有 `nexloop_twin_port` 用该世界的凭据能调用；real 与 test 世界被拒。
- act 先要 observe 过这一步，再经 NX-041 S7 的端口入口写事件，沿用每个世界 100 000 个事件的上限与重放规则。
- **来源标记**：事件的端口版本为 `twin.<digest 前缀>/<版本>`，属性带 `origin: twin`；`runtime.nexloop_twin_event_provenance` 按步记录区间、结果与校准状态。
- **端口原始 act 已收回**：端口角色不再能直接执行原始 act，孪生事件只能经 `nexloop_twin_act` 写入。

## 6. 预算（D6）

- 只运行受控清单 `control.nexloop_twin_generators` 中不调用模型的生成器，目前只登记了 `twin-template/1`；模型生成器以 `model_budget_required` 拒绝，等后续切片接上模型预算检查。
- 每个世界最多 100 次抽样运行、100 000 行，超出时以 `quota_exceeded` 拒绝。模型费用（以后接入时）计入 NX-041 的模拟预算账号。

## 7. 事实、假设、模拟输出与校准结论的区分

| 类别 | 在哪里 | 规则 |
|---|---|---|
| 事实（real 数据） | 只以 T4 的聚合进入校准 | 每组至少 30 个消费者，排除人设，不读个体 |
| 假设 | 孪生定义的 hypotheses | kind 只能是 `hypothesis`，写 `fact` 被拒；文本可擦除 |
| 模拟输出 | 只在 `sim:` / `shadow:` 世界的抽样与端口事件 | 带来源标记，不写入 Claims 或本体对象 |
| 校准结论 | 冻结的校准报告与只追加的校准事件 | 事件必须对应一份一致的报告；只有 `passed` 才使版本可选用 |
