# NX-023-C：Role Run 的 Context v6 与 relay 的 `--context-strategy`

依据：`NX-023-B.md`（消息 Run v6，迁移 0092）；设计稿 §3、§7、§8。基线 `dispatch/integration-s3r` `bc4dbca`。

## 1. 本步做了什么

| 部分 | 内容 |
|---|---|
| Role v6 包 | 冻结的 Role 核心原样保留：`bindings`、`formal_facts`、`current_constraints`、`supply`；`role = {role_binding, role_policy}`（v5 策略；无策略的 Run 为 null）；`current_event` = Role 服务触发（v3 `trigger_statement` 原样）；`user_statement` 为 null。其余段（策略、goal/控制快照、条目段、预算、insufficient）与消息 v6 相同 |
| 产出 | `RoleContextV6ArtifactProducer`（`role_context_artifacts.py`）：先走原 Role 链（stage → snapshot），再在 Source 当前权限下读来源：未确认执行（Consumer READ）、该 Consumer **所有会话**的 Claim 证据（新只读定义器列出会话，逐个会话要 Conversation READ；读不到的记 `required_source_unreadable`）、控制快照 |
| 选择 | `activate_role_plan(..., context_strategy=...)` 显式选择 v6；不传仍为 v3/v5 |
| 绑定（SQL） | `authz.nexloop_role_context_v6_command`：同一事务内调用冻结的 Role 命令（`snapshot`，自带签名信封）重新推导核心并逐键比较（`role`、`current_event` 也逐项比较）；首次绑定时调用共享的 `authz.nexloop_context_v6_sections`（策略/预算/Goal/控制快照/逐来源复核/被裁剪条目/钉住来源完整性，规则与 0092 消息 v6 相同）；按冻结 Role bind 的规则核对 Artifact（CREATE/READ 证明、principal、sha256、大小、保留期、object_key），写 `role_context_artifacts`（pack_text 为 v6）、`context_packs`、`context_sources` |
| Context id | Role Run 的效果上下文由同一 PlanStep 的所有 Run 共享，因此 Role v6 的 Context id（Manifest `context_id`）按 Run 派生：`runtime.nexloop_role_pack_context_id(run_id)`；`role_context_artifacts.context_id` 仍是效果上下文（Role 激活链的既有检查不变） |
| guard / Manifest | 0092 的请求快照外包层与 Manifest 投影改为经 `runtime.nexloop_context_v6_binding` 同时查找消息与 Role 的 v6 绑定 |
| 下游 | Role 激活链（0063/0064/0075/0085）不检查版本号，只读 `bindings`/`supply`/`formal_facts`，v6 原样保留这些段，因此无需改动；v3/v5 的 Role 复制读取（0087）对 v6 按未知协议拒绝 |
| Host | `context-input.ts` 的 v6 分支支持 Role 包：核心按 v3（无策略）或 v5（有策略）原规则校验，`user_statement` 必须为 null，事件必须是 `service_trigger` |
| relay CLI | `message_relay_cli --context-strategy <strategy_id>`（只接受策略 id 格式）；不传保持 v2 |
| 0092 复用 | 条目复核函数推广为会话集合版本 `authz.nexloop_context_v6_source_in`，0092 的单会话入口改为委托（行为不变）；0092 的消息绑定定义器本身未改动 |

## 1b. 人类专用的 Manifest 读取（负责人决定 2026-10-09）

| 部分 | 内容 |
|---|---|
| Action | `nexloop.context.audit:1`（capability `context.audit`，`authority=human_owner`），在 `deploy/configuration/business-actions.v1.json`（manifest_version 3）声明，经可信配置发布；读取范围类型 `ContextManifest@1` 在 `deploy/ontology/system-object-types.v1.json`（manifest_version 2）。**不进** `service-grants`；授权只给人类负责人/审计角色 |
| SQL | `authz.nexloop_context_manifest_read`（0094）：签名信封 → **先查身份**：`run_context` 非空（Run 凭据）或 `subject_kind` 不是 human（service、Agent）一律以 `human context audit authority required` 拒绝，此时还没评估任何授权 → 再校验当前 EXECUTE 授权、已发布定义一致、capability 为 `context.audit` → 在调用方租户 RLS 下返回 `runtime.nexloop_context_manifest` 的结果（无此调用时为 null）→ 尾部再校验授权 |
| Python | `context_engine/audit.py`：`ContextAuditReader(pool, human_session, signer).manifest(run_id, call_sequence)` |
| 投影 | owner 专用投影保持 owner 专用；修正一处确定性缺陷：`ontology_schema_revision` 改为只统计请求时刻已发布的类型版本，之后发布新类型不再改变旧调用的 Manifest |
| 未做 | HTTP 路由（浏览器人类入口）未加；当前入口为后端 Python 端口 + SQL 定义器 |
