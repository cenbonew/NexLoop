# NX-031 / AT-060 阶梯记录

AT-060（1000 客户与并发矩阵）按负责人 2026-10-12 的决定分级推进：**100 → 200 → 500 → 1000** 客户，每一级通过后再进入下一级。本文记录各级的结果、结论与在途修复，供后续各级对照。

- **运行环境**：CI 主机（8 核 16 线程笔记本级 CPU、13 GB 内存）。不写主机名或地址。
- **口径**：以下数据都是**模板构建的历史回复阶段**（为合成客户的历史来信生成回复），不是矩阵各格的稳态测量；Agent Host 用确定性测试档案，**没有注入模型时延**。
- **版本**：`08b2099`（含 ADR-027 inspect 授权范围、ADR-028 效应工具收尾复查）。
- 结果目录与报告格式见 [结果契约](NX-031-results-contract.md)，运行方式见 [车道运行说明](NX-031-lane-runbook.md)。

## 1. 各级结果

| 级别 | 回复 | 未回复 | Run 任务 | 失败 | 用时 | 回复速率 | 结论 |
|---|---|---|---|---|---|---|---|
| 100 客户 | 162 | 0 | 162 全部成功 | 0 | 705.6 s | 约 0.23 条/秒 | 通过 |
| 200 客户 | 299 | 0 | 299 全部成功 | 0 | 1487.3 s | 约 0.20 条/秒 | 通过 |
| 500 客户 | — | 待回复 770 → 629 时中止 | 积压 120 | 见下 | 约 4000 s 时中止 | — | 中止 |

**500 客户的失败构成**：

- 派发不可用 567 次：Run 在队列中等待约 300 s，超过 Run 凭据的有效期，派发时被拒；
- `runtime_failed` 59 次；
- 授权不可用 13 次；
- 数据库日志中约 6300 次凭据拒绝：效应 worker 用已过期的身份反复重查；
- 死锁 5 次。

**此前的两次 1000 客户整轮**（版本 `2923e56`、`fd2a39a`）都中止于模板历史回复阶段：0 条回复，约 0.09 条/秒，失败以授权超时为主。之后的 ADR-027、ADR-028 降低了每次授权的成本，100、200 两级随之通过。

## 2. 结论

- **正确性已干净**：100、200 两级没有失败、没有未回复，每个任务都成功；按结果契约的 7 项核对（越权、发错对象、拒收后联系、重复效应等），各级都没有违规记录。【待确认：500 级中止前的 7 项核对计数，以 CI 主机上的结果目录为准】
- **瓶颈在吞吐与积压**：回复速率随规模下降（0.23 → 0.20 条/秒）；到 500 客户时积压超过处理能力，Run 排队时间超过凭据有效期，派发失败由此放大，过期身份的反复重查又增加了数据库负担。

## 3. 在途修复（以合入 main 的为准）

| 修复 | 针对的问题 | 状态 |
|---|---|---|
| ADR-029：guard 复用 Source 签名的上下文信封 | 每次授权现场重建上下文信封的成本 | 负责人附条件批准，实现在途 |
| 派发失败分阶段错误码；过期 Run 终止 | 区分 Run 失败在哪个阶段；排队超过凭据有效期的 Run 直接终止而不是反复失败 | 在途 |
| relay 积压准入限流 | 积压超过处理能力时不再继续签发 Run | 在途 |
| 未知效应重查退避 | 效应 worker 用过期身份反复重查 | 在途 |
| 死锁定位 | 500 级的 5 次死锁 | 在途 |
| 事实规范化提速 | 授权事实解析的 CPU 成本 | 在途 |

## 4. 各级通过标准（L4 建议，以 CI 主机实测为准）

- 模板历史回复全部完成：未回复为 0；
- Run 任务失败为 0（或只有在结果契约中有明确归因、且不是正确性问题的失败）；
- 7 项核对违规为 0；
- 没有死锁；
- 用时与回复速率记录在案，作为下一级的对照。

具体阈值由调度员在每级运行前确认，结论写入 `planning/acceptance-tests.json` 的 AT-060 证据。

## 5. 下一步

1. 上述修复合入后，在 CI 主机上重跑 500 客户一级；
2. 500 通过后进入 1000 客户整轮（包含 C4-ci 与 NX-052 的端到端测量窗口）；
3. 1000 客户的结果出来后，由负责人作出容量决定（ROADMAP D-a）。
