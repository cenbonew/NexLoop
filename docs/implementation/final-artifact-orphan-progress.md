# Durable final Artifact orphan maintenance

NX-007 progress: final files now have an explicit absence-based maintenance path. Runtime-owner retention/deletion integration remains incomplete; no full S1/S2 or AT status is promoted.

## Implemented authority and durable protocol

FinalOrphanCollector / authenticated Backend.collect_final_artifact_orphans and resume_final_artifact_orphan_sweep require the exact restricted nexloop_domain_worker role AND actual EIOS DELETE on eios:artifact:orphans_<authenticated world>. Normal local Artifact DELETE authority does not grant final-orphan maintenance. No caller-supplied tenant/world/principal or Memory allow oracle is used. Each command resolves the actual twelve facts and signs nexloop-orphan-sweep-v1 with verb/request digest/identity/realm/fact epoch and a short expiry. SQL verifies the active signer, bound operation/resource, live credential and all dependency records. Applications get no raw ledger or business DML access.

A bounded filesystem page discovers only opaque 32-hex final names in the server-derived private tenant/world namespace. It snapshots regular service-owned files no larger than MAX_ARTIFACT_BYTES, old by the explicit cutoff (at least 60 seconds), including inode/mtime/size/SHA. Private directory FDs and nofollow/nonblocking opens protect traversal; symlinks and oversized/nonregular/recent files are retained. Unexpected I/O errors fail rather than silently appear successful. Discovery is not proof of orphanhood.

0018 adds FORCE-RLS runtime.nexloop_orphan_sweeps. A planned record commits before any unlink, storing only bounded opaque metadata and the page cursor. Execution freshly authorizes the plan, locks its row, then holds SHARE locks on local Artifact metadata and invocation/job tables through physical removal and final outcome commit. Any metadata row (any status or principal in the same tenant/world) protects the file. Any matching tenant invocation/job reference conservatively protects it, including terminal records. New reservation/reference writes cannot race the absence check under these table locks. This deliberately coarse initial maintenance lock is bounded to one page, not a performance claim.

Exclusive filesystem namespace flock serializes the physical operations with upload/fsync. Guarding again after lock waits and after each hash read rechecks PG expiry; it does not reuse a stale initial planning decision. Only eligible files whose current inode/mtime/size/SHA still match the durable snapshot are unlinked. Changed files remain; missing files reconcile as absent; registered/referenced files remain protected. Directory fsync runs even on partial failure. The outcome dispositions removed/absent/changed/protected persist with the completed plan. A transaction rollback after unlink leaves the previously committed planned record for authenticated resume; it does not pretend files roll back. Finished-plan replay returns its stored receipt.

Maintenance of unregistered files cannot prove a historical upload principal. It therefore requires an explicitly distinct tenant/world maintenance grant, and does not borrow another user's normal Artifact permission. No general runtime shell or raw file operation is exposed to agents. The original protected upload/retention path remains separate. No automatic scheduler, backup/deployment job or production sweep ran here.
