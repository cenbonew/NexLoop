# NX-011 HTTP browser authentication foundation

Optional server-owned BrowserConfiguration integrates a dedicated private identity pool into the native API lifespan. Private DSN and rate HMAC key files are read with existing strict file checks; startup failure keeps browser_store absent and routes fail closed. Pool/key references are cleared on shutdown. Optional CLI flags require a complete fixed HTTPS origin/tenant/App configuration; the console remains loopback/test-only and access logging remains disabled.

/api/v1/auth/login enforces exact Origin and Host, bounded streamed JSON with exact username/password keys, canonical server tenant and exactly one active canonical membership. It uses actual frozen password authentication/Evidence/Session creation or login replacement. Password verification and PG work are offloaded from the ASGI event loop to the worker threadpool. Policy-driven durable PG login rate limiting binds a server-key HMAC to the canonical origin and actual peer address; client forwarding headers are ignored. Behind a proxy, peer-level limiting is conservative and shared until trusted proxy configuration is implemented. Migration0032 explicitly permits the dedicated nexloop_identity operator in the existing protected rate function; it still requires operator=session_user and an active matching policy. No policy/counter table access is granted.

The Session cookie is __Host-nexloop_session, Secure, HttpOnly, SameSite=Strict, Path=/ with no Domain. Raw token is never returned in JSON. CSRF is returned to the same-origin login client with no-store; it is not persisted raw. GET/session uses current canonical Session inspection. POST/logout enforces Origin/Host and frozen current Session-bound CSRF then protected revoke; cookie is cleared. Unknown fields/credential errors are opaque and never echo request credentials. Realm/principal come from server config/canonical membership, not posted claims. This identity loop grants no business Action authority.
