# NX-042 T2 — decision layer and seeded population sampling

Scope: design §2, §5, D1, D4, D6, D7. Migration `0276_nx042_twin_sampling.sql` (temporary number, contiguous after T1's 0275; the dispatcher renumbers at merge). Contract `nexloop-twin-sample/1` (`packages/contracts/twin-sample.schema.json`).

- `authz.nexloop_twin_sample(digest, world, twin, version, seed, count)`, executable only by `nexloop_sim_api` with the world's api credential (S6c app_role); real and test are refused through `authz.nexloop_sim_effect_tenant`.
- Decision layer `runtime.nexloop_twin_decide`: every behaviour returns the version's `low`/`high`/`coverage` and one boolean `simulated_outcome`. A probability is drawn inside the interval and the outcome against it, both from the S3 sha256 draw; the drawn probability is never stored or returned (D4).
- Reproducible: the draw base is `seed | definition_digest`, Consumers are the world's synthetic Consumers ordered by id and cycled, and `output_digest` covers what the samples say (not the world or the run id). The same seed and twin version give byte-identical samples in any world; a repeated call returns the same run.
- D6: only a generator the controlled list (`control.nexloop_twin_generators`, T1) marks as calling no model runs; a generator that calls a model is refused with `model_budget_required` until a slice adds the model budget check.
- Ceilings per world: at most `runtime.nexloop_twin_sample_run_limit()` = 100 runs and `runtime.nexloop_twin_sample_row_limit()` = 100 000 sample rows (the NX-041 S7 port's ceiling: 100 runs of the 1 000-instance maximum). Beyond them a new run is refused (`quota_exceeded`); a repeated run is still answered. Runs in a world are serialised so the counts are exact.
- D7: runs and samples carry the twin's calibration status at sampling time, derived from its latest calibration event (`runtime.nexloop_consumer_twin_calibration`, T1; uncalibrated until T5). **The status on a run is a snapshot at sampling time, not the current status: a later calibration event does not change a stored run. Downstream (NX-043) must re-read the latest event (`runtime.nexloop_consumer_twin_calibration` / `_selectable`) before use.** Tested: a passed event then a failed one leave the stored run's status as it was while the current status follows the latest event. NX-043 selects through `runtime.nexloop_consumer_twin_selectable` only.
- Storage: `runtime.nexloop_twin_sample_runs` and `runtime.nexloop_twin_samples`, sim/shadow worlds only, simulated output, append-only (`sim_ledger_guard`), removed by the S2 whole deletion. Nothing is written to Claims or ontology objects.
- `nexloop_sim_api` WHITELIST in `tests/test_nx041_sim_roles_pg.py` gains the new function. No existing function is redefined, so the copy guard is unchanged.

Tests: `tests/test_nx042_twin_sampling_pg.py`.

Reproduction across worlds (L6 T2 review 2): the samples are byte-identical when both worlds were generated by S3 from the same frozen input (same seed and parameters, no extra generation), since the Consumers are the world's synthetic Consumers ordered by id. The behaviours alone depend only on the seed and the twin version.
