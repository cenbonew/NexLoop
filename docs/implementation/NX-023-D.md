# NX-023-D：模型调用结果、v4 关系并入 v6、v6 复制读取、relay CLI 端到端、人类审计 HTTP、绑定去重

基线 `nx023-c` `50ee7e2`。临时迁移 0095、0096。未改 `authorization.py`、`object_reads.py`、`service_offerings.py`、`role_runs.py`、授权 SQL 包装层（`nexloop_assert_*`）、`effect_*`、`runtime_dispatch`。`runtime_activation.py` 只增加 `model_result` 可选参数（开工时已告知调度员）。

## 1. 模型调用结果（0096）

- guard 外包层（0092/0093 定义）重定义：v6 Run 的 `model` 授权可携带 `model_result = {call_sequence, result_status ∈ succeeded|failed|unknown, usage{input,output,cache_read,cache_write,total}|null, cost(十进制字符串，≤8 位小数)|null, response_digest|null}`；原有全部检查先执行，结果在同一事务写入对应 `model_requests` 行（0089 触发器保证只写一次）。同一结果重试幂等；不同结果、无对应请求、与请求快照同时出现、形状不符一律拒绝；`succeeded` 必须带用量、费用与响应摘要。
- Host：`safeProviderStream` 增加 `settle` 钩子，在放出最终事件前等待结果写入；provider 报错记 `failed`，异常记 `unknown`（尽力），写入失败则本次调用失败。`response_digest` 为经过安全裁剪后的消息的规范 sha256；费用来自 Pi 的 `usage.cost.total`。
- 链路：Host → `runtime_control`（放行 `model_result` 键，只用于 `model`）→ `backend.authorize_runtime_activation` → `RuntimeActivationPort.authorize(model_result=…)`（形状预检）→ SQL。

## 2. v4 关系评估并入 v6（0095）

- v6 契约增加**可选**段 `relationship_context`（与 v4 段完全相同）；带此段的 v6 包，其核心由冻结的 v4 链（`nexloop_relationship_context_artifact_command`）在 SQL 内重新推导并逐键比较，因此 v4 规则原样保留：当前陈述只能是已解决的用户陈述，hypothesis 只能作为证据。关系行以原 epistemic_kind 记入 `context_sources`（hypothesis 只在 evidence 段）。
- 运行激活链：v4 的关系快照比对、关系期限与正式对象现时性检查，对带关系段的 v6 包同样执行（`authz.nexloop_context_has_relationships`；为避免 AND 求值顺序问题改为嵌套 IF）。
- relay 不再拒绝“关系 recipe + 策略”同时指定；Host v6 解析带关系段时按 v4 规则校验核心，确定性关系模式也允许 v6 配置。

## 3. v6 复制读取（0095）

- `nexloop_context_artifact_read_dependency_v2` 与 `nexloop_read_local_artifact` 各加一层（原函数改名为 `*_before_v6`，非 v6 一律委托原链，行为不变）。
- 对 v6 包，SQL 从已绑定的包推导读者必须持有当前 READ 的全部来源对象：触发 Message（actor、body）；Role 包则为 RoleDefinition / ConsumerRoleLink / PlanStep，且只允许产出它的 Source 读取（与 v3/v5 相同）；四个正式对象（EffectControl 含 4 个属性）；供给的 ServiceOffering / ConsumerServiceOffering 及字段；关系评估（全部字段）；被引用 Claim 所在的 Conversation；有 open_work/正式状态时的 Consumer（含展示的属性）。调用方提交的读取信封必须与 SQL 推导的集合逐项一致，每项经 `nexloop_role_strict_read` 复核，最后核对 Artifact 读取许可与摘要。
- Python：`postgres_artifacts.get` 对 `kind='v6'` 按 SQL 给出的清单用读者自己的会话构造读取信封。

## 4. relay CLI 子进程端到端

`message_relay_cli --context-strategy recent_plus_required` 在独立进程中完成 v6 绑定并入队；未发布的策略在进程内 relay 上失败关闭（不绑定、不产生 Artifact）。

## 5. 人类审计 HTTP 路由

`GET /api/v1/context/manifests/{run_id}/{call_sequence}`（`context_audit_http.py`，照评审工作台写法）：同源检查、浏览器会话非受限、经 `authenticate_browser_business` 得到人类会话后调用 `ContextAuditReader`（0094：先身份后授权）。200 返回 Manifest，404 无此调用，401 未登录，403 跨源/无权，422 参数非法；只有 GET。

## 6. 0092/0093 去重（0095）

消息 v6 绑定定义器在 0095 中重定义为调用 0093 的共享段校验函数 `authz.nexloop_context_v6_sections`（0092、0093 文件不改）；0092 的 16 种篡改用例全部以原消息通过。
