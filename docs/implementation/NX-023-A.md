## 模块 `nexloop_eios/context_engine/`

- `strategy.py`：策略校验（键、协议 v6、预算/框架预留、各段配额、裁剪顺序须为全部步骤的一个排列、语义参数；real 世界禁止 hypotheses；永不允许 rejected_definition）；`StrategyPublisher`（人类受治理发布）；`StrategyRegistry`（读当前/指定版本并复核 SQL 计算的 jsonb 摘要）；`load_builtins`。
- 内置策略：`deploy/configuration/context-strategies.v1.json`（`recent_plus_required@1`、`ontology_hybrid@1`，只在证据选择上不同），由人类 owner 经上述 Action 发布，迁移里没有种子数据。
- `budget.py`：`ConservativeEstimator`（ceil(UTF-8 字节/2)+8，对中文与 ASCII 都高估，不按字符计）；`apply_budget`：段配额 → 必需段/钉住项（否定、联系限制、未确认执行）超预算即 `mandatory_exceeds_budget`（不截断）→ 按策略顺序裁剪 → 仍超则裁核心业务并报 `core_trimmed`；`budget_report` 含各段计数/估算 token 与每条省略原因。
- `sections.py`：分区规则（与 0089 的 CHECK 同一套）：Claim 只进 `evidence.claim_evidence` 且只有原文（无结构化值）；`rejected_definition`/`superseded` 不进；hypothesis 默认不进、研究策略开启时只进 `evidence.hypotheses`；外发未被渠道接受的只作为 `open_work` 执行状态，已接受的通过会话流作为对话证据。
- `semantic.py`：`SemanticAdapter.browse/resolve`（NX-021 召回 + SQL 定义读取；输出 version/coverage/ambiguity/source_refs/access_decision_refs；歧义只报告不自动选）；`OpenWorkReader`。
- `authority.py`：用公开 EIOS 决策 API 生成当前 READ/EXECUTE 证明与签名读取，不修改 `object_reads.py`。

## 留给 NX-023-B / 待决定

- 写入方：v6 Pack 绑定、来源逐条 SQL 复核、guard 的 `request_snapshot` / `model_result`（会碰 L1 文件）。
- **契约提案**：`context-manifest.sources[].evidence_kind` 现为 `verified_fact|user_statement|hypothesis|policy|schema|memory|current_message`；本线内部分区需要 `formal_object`、`conversation`、`execution_state`（0089 已按内部集合约束）。建议契约改为内部集合（或增加这三项），避免把正式对象状态误标为 `verified_fact`。
- **授权清单**：`nexloop.context.assemble:1`（Context 组装服务主体）需进入 `service-grants`；`nexloop.context.strategy.publish:1` 的 Action 定义需进入业务 Action 清单——当前 `business_actions.py` 只支持 `ontology.object.create`，需要扩展或另立清单（调度员决定）。
- 别名展示的正向用例需要真实候选/合并夹具（别名行外键到候选），本步只覆盖空别名。
- 策略发布目前不推进 NX-022 控制 revision；若策略变更应使旧计划失效，需与 NX-024 一起决定。
