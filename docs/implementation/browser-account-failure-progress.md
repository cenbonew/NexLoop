# NX-011 durable local-account failure port

Added append-only 0022_browser_account_failures.sql and PostgresBrowserLocalAccountRepository.record_authentication_failure/current_time. The protected function is restricted to the actual nexloop_identity session/operator and configured active Application. It locks and rechecks canonical active Human Subject and account, uses database time, serializes current account state, atomically updates failure/revision/lockout state and appends a nonsecret login-event record. A still-valid lock is returned unchanged; stale concurrent attempts cannot clear or shorten it. Direct credential/audit access remains denied. There is no password-hash or business-object write in this operation.

The policy follows the actual frozen EIOS identity/ports.py and migrations/0053_identity_sessions.sql: five failures cause a 15-minute lock, then 30/60 minutes, capped at 60. PostgreSQL clock and existing row state arbitrate concurrent operations. No user-supplied clock can create a future failure; missing/wrong tenant/operator, revoked Application and untrusted role fail closed. Model decoding occurs inside the transaction before commit, so an invalid returned snapshot rolls back counter and event together.

Refactored the existing typed LocalAccount decoder into a shared helper. The reader still reconstructs EncodedPasswordHash/history and aware datetimes, never leaking credential material through repr/public response. The new repository is partial: it does not claim save_local_account, authentication-evidence issuance or SessionCreationUnitOfWork.
