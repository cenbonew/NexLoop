# NX-011 atomic new Session creation

PostgresBrowserSessionUnitOfWork combines the actual frozen password Evidence store with a new-session creation port. Migration 0026 persists only token/CSRF digests and nonsecret Session payload. Global Session-ID/token-digest uniqueness and FORCE RLS apply; no identity role direct table access. The protected function checks real session_user operator and configured tenant/App, takes an exclusive Evidence lock before inspection to avoid shared-to-exclusive upgrade deadlocks, reloads the exact current canonical identity/App facts under locks, and locks/revalidates membership status, subject, revision and validity. Session binding must exactly match Evidence, including restriction. Creation timestamps and configured seven-day idle/thirty-day absolute limits are checked at DB boundary.

Evidence consumption and Session insertion are one transaction, with exact reply comparison before commit. Commit failure rolls back both. The opaque proof and raw session/CSRF tokens are never stored. Duplicate/stale/expired/consumed Evidence is not accepted, and no standalone consume is exposed. The port only handles new sessions; replaced-session commands fail closed pending atomic replacement support.
