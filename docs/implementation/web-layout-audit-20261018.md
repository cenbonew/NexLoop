# 网页端适配审计（2026-10-18，只读）

**依据**：负责人 2026-10-18 反馈：“各个平台的展示交互优化，目前好多页面不适配 WEB”。本轮只审计，不改代码。修复要等 L3 的工作台“真实派发开关按钮”合并后再派，因为它也会改 Settings、Overview 和 `styles.css`。

## 1. 方法

- **环境**：本机冒烟栈 `scripts/dev/workbench_smoke.sh`（`.claude/launch.json` 中的 `workbench-smoke`）：
  - 临时 PostgreSQL，生产 API（确定性测试 profile，`REAL_DISPATCH_ENABLED=false`），Web dev server；
  - 只有合成数据：一个租户，owner 和 operator 两个工作台成员，一个顾客及一段会话、一条来信；
  - 基于 main 84d2985b。
- **截图**：用无头 Chromium（Playwright）截全页图：
  - 五种尺寸：1440×900、1280×800、1024×768、768×1024、390×844；
  - 暗色模式（`prefers-color-scheme: dark`）在 1440 和 390 两种尺寸下截；
  - 共 19 个页面、133 张图。
- **测量**（同时由脚本采集，见 `metrics.json`）：横向滚动量、主内容宽度占视口的比例、表格是否溢出、表头最大高度（用来判断是否换行）、文字的最小字号和中位字号、超出视口右边界的元素数、导航的位置和尺寸。
- **截图与测量数据的位置**：`local-only/audit/web-layout-20261018/`（被 git 忽略，不提交）：
  - 文件名为 `<页面>-<宽>x<高>[-dark].png`；
  - 测量数据在 `metrics.json`；
  - 复现脚本为 `audit-shots.mjs`（需要先启动冒烟栈）。
- **没有覆盖的**：
  - 官网演示页 `/nexloop/`：本仓库中找不到（Caddyfile、`apps/web/public` 和各处 HTML 都没有），它在本仓库之外，需要给出它的来源或 stage URL 后另行审计；
  - 参考端点 `/staff`：本轮没有重新截图。它在 2026-10-17 已经单独修复（main 4839c4d2：桌面表格、北京时间、视图、状态颜色），当时只实测了 1024 和 1440 两种宽度，见 §3.4。
  - 部分页面只有空状态，因为冒烟数据只有一个顾客：承诺、计划、Action 都没有数据，表格较多时的情形没有覆盖到，见 §5。

**严重度**：
- **阻塞**：某个尺寸下无法完成主要任务；
- **明显**：能用，但一眼可见地不适配；
- **细节**：观感和一致性问题。

## 4. 修复方案

### 4.1 统一的布局栅格与断点

改为**一套断点、一组尺寸变量**，写在 `styles.css` 顶部，顾客端和工作台共用：

| 名称 | 宽度 | 布局 |
|---|---|---|
| `sm` | <640 | 单列；页面边距 16 px；导航收进顶栏的“菜单”按钮（展开为全屏列表）；表格改为卡片列表，或横向滚动并给出提示 |
| `md` | 640–1023 | 单列内容，加顶栏菜单；内容最宽 720 px；工作台卡片两列 |
| `lg` | 1024–1439 | 工作台：240 px 固定侧栏，加流式主区；卡片三列；顾客端：主内容 880 px 居中 |
| `xl` | ≥1440 | 同 `lg`；工作台主区最宽 1440 px 居中；顾客端最宽 960 px |

**变量**（`:root`）：
- 间距 4/8/12/16/24/32；
- 圆角；
- 字号：正文 15 px（工作台）和 16 px（顾客端），辅助文字 13 px，表头 13 px，加深对比；
- 颜色：`--bg`、`--surface`、`--text`、`--muted`、`--border`、`--accent`；
- **暗色**：在 `@media (prefers-color-scheme: dark)` 中重定义同一组颜色变量（G1）。

**删除** `main` 的 `transform: translateX(44px)` 和 524 px 定宽，改为按断点设置 `max-width` 并居中，Logo、正文、页脚共用同一条左边界（G4）。

### 4.2 分批

| 批次 | 内容 | 涉及文件 | 前提 |
|---|---|---|---|
| **第 1 批：基础与外壳**（明显问题中占比最大） | 统一断点与变量（4.1）；暗色模式（G1）；顾客端去掉偏移、居中、主次按钮（G4、G6，按钮改为自适应宽度，只有主操作保留强调色）；工作台 `md`/`sm` 的顶栏菜单代替横向滚动条（G3）；工作台登录页改为居中的卡片；字号与对比（G5） | `apps/web/src/styles.css`、`Brand.tsx`、`App.tsx`、`Login.tsx`、`Account.tsx`、`workbench/WorkbenchApp.tsx` | **L3 的开关按钮合并之后**（它会改 `styles.css`） |
| **第 2 批：聊天与表格** | WebChat 版式：会话信息收进顶栏，消息区加输入框贴底的布局，对话选择显示标题或时间而不是 ID（G7）；工作台表格在 `sm` 下改为卡片列表，或给出横向滚动提示，并调整列宽（消费者表等）；时间统一显示为本地时间（G7） | `WebChat.tsx`、`MessageReceipt.tsx`、`chat-api.ts`（如需展示字段）、`workbench/pages/Consumers.tsx`、`Commitments.tsx`、`Actions.tsx`、`Observability.tsx`，以及一个共用的表格组件 | 第 1 批 |
| **第 3 批：细节** | 总览卡片改为不等高的瀑布或自适应高度；会话页气泡宽度；`/staff` 补 390 宽度的检查；空状态统一样式 | `workbench/pages/Overview.tsx`、`Page.tsx`、`styles.css`、`apps/reference-endpoint/reference_endpoint.py`（只调样式） | 第 2 批 |

**每批的验收**：用 `local-only/audit/web-layout-20261018/audit-shots.mjs` 重跑五种尺寸加暗色，要求：
- 所有页面 `hscroll=0`，`offscreen=0`（`sm` 下导航收进菜单后应为 0）；
- 表头一行；
- 最小字号 ≥13 px；
- 暗色截图与亮色截图不同。

把这些写进 `apps/web/test/browser/` 的一个新浏览器测试（参照 `workbench-desktop.browser.mjs`）。

## 5. 限制与后续

- 冒烟数据量很小，所以表格多行、长文本、长会话的情形只能看出结构，看不出数据量大时的表现。第 2 批开始前，建议给冒烟栈加一组“多数据”的合成种子：几十个消费者、多条承诺和 Action。
- `/nexloop/` 演示页需要提供来源后再审计。
- 知识工作台对 owner 返回 403，需另开一项排查，不属于本批。
