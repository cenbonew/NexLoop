# 测试与验收计划

## 1. 证据等级

本交接没有运行项目集成/性能测试。Codex 的结果报告必须区分 `not_run`、`passed`、`failed`、`blocked`、`skipped`。关键PG、授权、Action、恢复测试不可在缺依赖时用skip计为通过。单元mock通过不代替真实PostgreSQL角色测试，合成业务事件不代替真实商业验证。

测试分为：纯函数/Schema单元；真实PG契约与RLS；Pi存储conformance；确定性模型的工作流测试；受控真实Provider smoke；故障注入；前端E2E；负载；备份恢复；开源干净安装。

## 3. 故障注入执行方法

在已登记的合成/测试tenant中，在入站提交、outbox发布、Run提交、工具意图提交、外部接受、结果记账、索引提交等边界设置failpoint。使用确定性测试渠道模拟“外部成功、响应丢失”，并保存其独立效应账本。每次只杀目标进程或隔离指定连接，禁止对原EIOS生产服务操作。

先记录预期效应数，再kill/restart/retry，最后比较PG账本、Provider账本、Run事件和实际消息。不能只看“服务又起来了”。SQLite恢复用实际持久后端，NORMAL/FULL差异、owner锁和版本兼容分别测试。

## 4. 负载与SLO（初始验收目标，需实机校准）

数据基线：1,000合成消费者、100,000消息、20,000记忆、固定数量的关联对象/承诺；生成器固定seed并输出精确计数。测试第二租户用于串用检查。

平台测试使用确定性Provider，先在无CI构建时测，再在受限CI构建同时测。矩阵为Agent并发1/2/4/8；消息入口持续10 events/s 10分钟与100条瞬时重投/新消息混合，分别报告可接收量、排队时间、最老任务age、处理吞吐和错误，不把接受速度当LLM处理速度。

初始目标：入站ACK p95≤500ms；普通受权详情p95≤500ms；空闲交互队列调度p95≤2s；任务lease过期回收≤60s；已接受事件静默丢失0。过载时保留事件、返回明确限流并公平排队，不保证无限吞吐。

真实模型单独测试至少20条受控交互，报告模型/工具/平台时间及费用，不用如此小样本对稳定p95做统计承诺。发布前按目标用量增补样本；最终并发由实际报告选取，不由消费者数量推导。

## 5. 知识质量与评估

构建至少100个带标签的中文合成抽取案例，覆盖否定/条件/时效/身份/冲突，关键不可变条件必须100%符合（无越权、无错误付款、无明确拒绝被忽略）。可将非关键Claim宏平均F1≥0.90作为初始改进目标；标注标准与集合冻结，不能删掉失败例提高分数。

真实脱敏评估按消费者或会话簇分组，避免近重复泄漏。Evo候选除评分外必须通过引用、兼容、权限、索引和迁移硬门槛。任何模拟/影子回放都没有真实外部效应权限。

## 6. v0.1 Definition of Done

S0–S5所有必需任务完成并有证据；AT中S1–S5用例通过；真实PG与Pi恢复测试通过；工作台和消费者WebChat端到端可用；两机TLS/角色/端口/备份验证；一个受控真实模型和真实交付动作完成；无TOS/旧生产系统/GitHub在线CI强依赖；发布与恢复手册可由另一维护者执行。

缺真实渠道/模型凭据时其测试可blocked，其他工作继续，但不能把release标为完成真实运营验收。S6/S7未做不影响v0.1，但界面与README必须准确标记阶段。

## 7. 发布证据包

保存environment inventory、commit/digest、lock hashes、catalog版本、测试命令和原始结果、首次失败/重跑记录、恢复步骤、效应对账、性能数据、许可/SBOM和已知风险。给出结果来源，不使用演示截图代替执行证据。
