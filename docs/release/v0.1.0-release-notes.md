## What v0.1 is

NexLoop is an open-source **continuous-operations system** for enterprises: an owner sets goals and key results, and Agents work inside governed Action boundaries to understand consumers, fulfil commitments and deliver value, adjusting plans from real outcomes.

v0.1 is the **controlled real closed loop**: one tenant, one real interaction channel (native WebChat), one real delivery action, one controlled real model — with **reliable real-world actions before** consumer digital twins or simulated strategy selection. The controlled real closed-loop acceptance tests (AT-071, AT-072) have passed. `v0.1.0` is tagged once the NX-037 evidence pack is complete; there is no release candidate (D-tag-1).

This project is exploratory. It does not promise more revenue or payment, and interfaces and data structures may still change.

## What is included

Summarised from the [CHANGELOG](../../CHANGELOG.md); the architecture is described in [docs/ARCHITECTURE.md](../ARCHITECTURE.md).

- **Governed actions and reliability**: only published EIOS Actions change formal business objects or cause external effects; stable business-intent IDs, persist-before-ACK, query-and-reconcile before any retry of an unknown outcome; the three-layer real dispatch switch (deployment, tenant, tenant + Action), closed by default, owner-only.
- **Conversation to ontology**: topic segmentation and Claim extraction with source spans, hybrid recall, four-layer matching, candidate definitions with gluing and human review.
- **Goals, plans and context**: versioned goals and key results, the control plane (pause, budgets, contact restrictions, takeover), plan re-evaluation, context engine v6 with per-source authorization and recorded model requests.
- **Customer protection**: deterministic "do not contact me" hard stop, guaranteed reply to inbound messages, contact-key interception after deletion, owner-only release.
- **Commitments, commercial events and incentives**: evidence-based commitment fulfilment, signed commercial events, costs and key results, catalogue-bounded incentives with budget checks at dispatch.
- **Owner workbench**: role-based pages and governed actions, human takeover and staff replies, audit.
- **Privacy and data lifecycle**: retention by data class, consumer and message erasure with restore-time replay, governed export.
- **Operations**: metrics and alert rules, backup manifest, restore journal and restore fence, migration gate without waivers, local release tool (manifest, sign, verify, rollback check), local CI controller, open-source compliance checks.
- **Runtime**: Pi Durable Agent Host in its own network namespace, multi-process guard, bounded authorization retry, multi-consumer message relay.

## Not included and known limitations

The authoritative list is section 6.2 of [docs/ARCHITECTURE.md](../ARCHITECTURE.md) and the "Known limitations" sections of the [CHANGELOG](../../CHANGELOG.md). At the time of this draft:

- **Deployment**: deployed and accepted on one two-host stage only (final acceptance release: release 22); server steps are performed or confirmed step by step by the owner.
- **Real outbound effects**: only one real delivery Action has been enabled (enterprise delivery, through the reference endpoint), and the three switch layers were closed again after the controlled trial; no other external channel is connected.
- **Capacity**: v0.1 is stated for **200 consumers** with a sustained inbound rate of at most **0.1 messages per second** (owner decision D-a); the load acceptance AT-060 passed on 2026-10-13. 500 and 1,000 consumers are not supported in v0.1.
- **Known risks**: see [known-risks-v0.1](known-risks-v0.1.md) (Chinese), for example CI test isolation relying on nft only, model provider address drift, and API pools needing a restart after a PostgreSQL restart.
- Incentives use a loopback channel only and have no workbench page; staff replies are WebChat-only; the simulation world has no Twin yet; EvoOntology is not installed.
- **ACK rises during configuration publication**: while a tenant publishes its configuration, inbound acceptance for that tenant may wait up to 0.2 s (measured ACK p95 about 425 ms, +18%, still under the 500 ms gate). This is an intended lock conflict and has been accepted; see the 2026-10-14 known limitation in the CHANGELOG.

## Deployment prerequisites

- Two hosts by role: **APP_HOST** (gateway, API, workers, Agent Host) and **DATA_HOST** (PostgreSQL 18 with pgvector, Valkey 8.1). Addresses, users and paths come from private configuration and are never part of the release.
- Deployment premises: Agent Host global concurrency ≤ 4, guard 4 processes, application connection pools ≤ 60 with `max_connections` ≥ 80 (checked by `nexloop-doctor`).
- Images are referenced by digest from a signed release manifest; real model credentials are provided by the operator; without them only the explicit test mode is available.
- See [docs/OPERATIONS.md](../OPERATIONS.md) and the [NX-032 deployment runbook](../implementation/NX-032-deploy-runbook.md).

## Upgrade and migration

This is the first release: **fresh installation only**. The migration lineage is `nexloop-eios-v1`, revisions `0001`–`0221`, applied by `nexloop-migrate`, which refuses to run without a verified backup (no waivers). There is no upgrade path from earlier, unreleased builds.

## Reporting security issues
