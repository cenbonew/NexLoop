### 0.3 主机、配置和占位符

| 占位符 | 含义 |
|---|---|
| `<DATA_HOST>`、`<APP_HOST>` | 两台 stage 主机的 ssh 名（私有 ssh 配置里的别名，不写进本单） |
| `<检出>` | 各主机上 main（≥ 批次 147）的检出目录 |
| `<RD>` | 三份配置共用的 `results_dir`（三台机器上路径相同） |
| `PRIVATE.json` / `DATA.json` / `APP.json` | 见 X7 执行单“主机、角色和配置”；`tenant_id`、`inputs`、`results_dir` 必须相同 |
| `<owner 条目>` | 执行 owner 阶段的工作台账号在 Keychain 里的条目名，例如 `nexloop/stage/approver3`。用哪个账号由负责人定，本单不写死 |
| `<顾客别名>`、`<顾客条目>` | S3、O2 发言用的合成顾客（customer-5 或其他，不用 s6c）及其 Keychain 条目 |
| `CUSTOMERS.json`、`PLAN-S3.json`、`PLAN-O2.json` | 合成顾客发言工具的配置和计划，两份计划的 `plan_id` 不同 |

**口令的传法**：只用 `security find-generic-password -s <条目> -w | 命令` 这一种形态，经 stdin 交给脚本，`nx043_stage.py` 只读一行。口令不进 argv、环境变量、heredoc、文件或日志。下面每条 owner 命令都由**负责人在自己的终端**执行。

在调度员机器上先定义一个找最新结果文件的函数（bash；文件名是 `<check>-<时间>.json`）：

```bash
latest() { ls -t "<RD>"/"$1"-*.json | head -1; }
```

主机上用同样的函数。下文写成 `$(latest nx043-probe-before)`。

**每个 owner 阶段之后**（S1、B1、S2、S7、O1、O4），调度员都把状态文件拷到两台主机：

```bash
scp "<RD>/nx043-state.json" <DATA_HOST>:"<RD>/" && scp "<RD>/nx043-state.json" <APP_HOST>:"<RD>/"
```

**每一步都先 `--dry-run`**（不连接，也不写结果文件），看过 `plan` 再执行正式命令。任何一步 `passed` 不是 true，或者有 `blocked` 项，就停在那一步，按该段的“失败”处理，不要跳到下一步。

## 3. NX-057 K4j：暂停补救，看过后恢复（S9 之后，NX-056 之前）

放在这里的原因：S4–S8 之外（补救开关的记录会进开关摘要）；O1–O5 之外；NX-056 开始之前就已恢复，不会混进 NX-056 的审计和告警。

- **执行者**：approver3（合成 owner），在工作台操作；负责人也可以代替。这个动作不在审批策略内，提交后立即生效。
- **判定者**：调度员，用只读查询判定；K4j 的界面结论由 L6 判。
- **只读会话 `ro`**：见 `run-nx057-remediation-stage.md` §0.3。

| # | 动作 | 预期与核对 |
|---|---|---|
| K1 | 暂停前核对 | `ro "select revision, paused, recorded_at from control.nexloop_remediation_switches where tenant_id='$TENANT_ID' and world='real' order by revision desc limit 1"`：记下 revision N。最新一条应为 `paused=f`（或没有行）；如果已经是 `t`，跳到 K3，K2 不做 |
| K2 | approver3 在“运营 → Action / 异常 → 补救”点“暂停补救”，原因填“K4j 演示：暂停” | 再查 K1：revision N+1，`paused=t`。页面摘要显示“补救已暂停”。截图：补救操作区和上方的列表或空状态之间有间距，没有重叠（K4j）。下一轮评估后 `remediation_paused`（warning）触发，这是预期的 |
| K3 | 看过后，approver3 点“恢复补救”，原因填“K4j 演示：恢复” | 再查 K1：revision 再加 1，`paused=f`。页面不再显示“补救已暂停”，下一轮评估后 `remediation_paused` 解除 |

- **耗时**：约 15 分钟，其中两次各等一轮评估（≤1 分钟）。
- **失败**：K3 之后告警 5 分钟内没有解除，或者最新一条仍是 `paused=t`：**不要开始 NX-056**，先查 `plan-reevaluator` 是否在运行。暂停期间补救不会生成，负责人手动唤醒也会被挡住，所以 K2 到 K3 之间不要超过 15 分钟。
