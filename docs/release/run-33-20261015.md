## 运行环境的决定（M13，均按代码推出）

| 项 | 取值 | 依据 |
|---|---|---|
| 在哪里运行 | APP_HOST 的演练卷 | M13 定案；repo1 在 APP_HOST 本地，可以按本地路径读取，不经过 TLS server |
| 运行 `nexloop-restore` 的 OS 用户 | **`nexloop-pgbackrest`** | `materialize_pgbackrest` 以当前用户运行 `pgbackrest restore`，需要读 repo1，而 repo1 的属主就是它；`pg_ctl start` 也以当前用户启动实例，所以 pgdata 的属主必须是它。另外，`read_private_text` 要求 pgBackRest 配置文件、标记文件都属于当前 euid、权限 0600 |

| `--owner-user` | **`nexloop_bootstrap`** | 这是 DB 角色，不是 OS 用户。代码以它经本机 socket 连接（`dbname=postgres user=<owner-user>`），执行 `set local role nexloop_owner`、把其他 `nexloop_*` 角色 `alter role … nologin`、调用 `runtime.nexloop_restore_*`。这些需要超级用户，而库里唯一的超级用户就是 `nexloop_bootstrap`。M9 已把它的 NOLOGIN 推迟到 3.2 之后，所以恢复出来的库里它仍可登录（见 0.1 的核对） |

| `--pg-bin` | 主机 postgresql-18 的 bin 目录，Debian 系为 `/usr/lib/postgresql/18/bin` | 代码会用到其中的 `pg_ctl` 和 `pg_controldata` |

## 3. APP_HOST：演练用 pgBackRest 配置（B 类；口令由负责人输入）

配置只有 `[global]` 一节，按本地路径读取 repo1，**不含任何 archive-push 设置**，所以演练实例从不向 stanza 归档。另外，代码在恢复时传入 `--archive-mode=off`，并在 `postgresql.auto.conf` 中写入 `archive_mode = 'off'`。

第 1 条写入不含口令的部分（umask 077，文件属主 `nexloop-pgbackrest`，权限 0600）：

```
sudo -u nexloop-pgbackrest sh -c 'umask 077; cat > "'"$D"'/conf/pgbackrest-drill.conf"' <<EOF
[global]
repo1-path=/srv/nexloop/backups/pg-repo1
repo1-cipher-type=aes-256-cbc
lock-path=$D/lock
log-path=$D/log
log-level-file=off
log-level-console=warn
EOF
```

第 2 条由负责人在同一终端执行：从密码管理器复制 repo1 的 cipher 口令，在 `getpass` 提示处粘贴。输入不回显，口令也不出现在命令行、shell 历史或日志里：

```
sudo -u nexloop-pgbackrest python3 -c 'import getpass; v=getpass.getpass("repo1 cipher pass: "); f=open("'"$D"'/conf/pgbackrest-drill.conf","a"); f.write("repo1-cipher-pass="+v+"\n"); f.close()'
sudo stat -c '%a %U %s' "$D/conf/pgbackrest-drill.conf"
sudo -u nexloop-pgbackrest pgbackrest --config="$D/conf/pgbackrest-drill.conf" --stanza=nexloop info
```

- **判据**：`stat` 输出 `600 nexloop-pgbackrest <字节数>`；`info` 能列出与 0.1 相同的 full 备份（口令正确时才能解密 backup.info）。
- **撤销**：`sudo shred -u "$D/conf/pgbackrest-drill.conf"`。

## 4. DATA_HOST：打恢复点（drill-mark）与 RPO 计时（B 类；DATA_HOST sudo 由负责人）

第 1 条在 APP_HOST 上打时间参照，用于计算 RPO（逐步授权）。两台主机的时钟须已同步，先用 `timedatectl` 看两边都是 `System clock synchronized: yes`：

```
sudo -u nexloop-pgbackrest touch "$D/report/before-mark"
```

第 2 条在 DATA_HOST 上，由负责人执行。`drill-mark` 以 recorder 身份调用 `authz.nexloop_drill_mark`：在同一事务里取各只追加表的计数和抽样行哈希，然后 `pg_create_restore_point('drill-<DRILL_ID>')`，记一行 `runtime.nexloop_restore_drills`，并把标记写进一个新的 0600 文件（文件已存在就拒绝）：

```
sudo install -d -o nexloop-backup -g nexloop-backup -m 0700 /srv/nexloop/backups/file-repo1/drill-<DRILL_ID>
sudo -u nexloop-backup /opt/nexloop/backup-venv/bin/nexloop-backup drill-mark --recorder-dsn-file /srv/nexloop/secrets/backup/recorder.dsn \
  --drill-id <DRILL_ID> --out /srv/nexloop/backups/file-repo1/drill-<DRILL_ID>/mark-<DRILL_ID>.json
```

- **预期输出**：`{"ok": true, "restore_point": "drill-<DRILL_ID>", "marked_at": "...", "tables": N}`。记下 `marked_at`。
- 标记文件里只有计数、哈希、catalog 和 LSN，没有凭据，也没有业务内容。
- **撤销**：不撤销。恢复点和 drill 行都只追加；同一个 `<DRILL_ID>` 不能再用，重做时换一个新 id。

**产物传递**：把标记文件送到 APP_HOST 的 `$D/conf/`，属主 `nexloop-pgbackrest`，0600（`read_private_text` 要求它属于运行恢复的用户）。按下面三步走，都经负责人的登录用户中转，不需要两台主机互相信任：

```
# DATA_HOST（负责人）：
sudo install -o "$USER" -m 0600 /srv/nexloop/backups/file-repo1/drill-<DRILL_ID>/mark-<DRILL_ID>.json ~/mark-<DRILL_ID>.json
# 管理机：
scp "$SSH_ALIAS_DATA:mark-<DRILL_ID>.json" "$SSH_ALIAS_APP:mark-<DRILL_ID>.json" && ssh "$SSH_ALIAS_DATA" rm ~/mark-<DRILL_ID>.json
# APP_HOST（逐步授权）：
sudo install -o nexloop-pgbackrest -g nexloop-pgbackrest -m 0600 ~/mark-<DRILL_ID>.json "$D/conf/mark-<DRILL_ID>.json" && rm ~/mark-<DRILL_ID>.json
```

**等待恢复点所在的 WAL 段归档**。`archive_timeout` 是 60 秒，所以等 3 分钟，然后在 APP_HOST 上找出参照时间之后第一个进入 repo1 的 WAL 文件：

```
sudo find /srv/nexloop/backups/pg-repo1/archive/nexloop -type f -newer "$D/report/before-mark" -printf '%T@ %f\n' | sort -n | head -1
```

- **判据**：至少有一行输出。没有输出就再等一分钟；超过 10 分钟仍没有，说明归档异常，停下报调度员。
- **RPO**：取这一行的时间戳（epoch 秒）减去 `marked_at`（`date -d '<marked_at>' +%s`），即恢复点进入备份所需的秒数，也就是本次演练测得的 RPO。门槛是 ≤ 300 秒（D2）。

## 5. 恢复日志：restic → APP_HOST（B 类；DATA_HOST sudo 由负责人）

在 DATA_HOST 上，由负责人从 restic repo1 恢复最新一份 `journal` 快照，打包后经负责人的登录用户中转：

```

sudo -u nexloop-backup restic --no-cache -r /srv/nexloop/backups/file-repo1/restic --password-file /srv/nexloop/secrets/backup/restic-repo1.pass restore latest --tag journal --target /srv/nexloop/backups/file-repo1/drill-<DRILL_ID>/journal-out

然后同第 4 步，经管理机把 `journal-<DRILL_ID>.tar` 拷到 APP_HOST。在 APP_HOST 上（逐步授权）：

## 6. APP_HOST：运行恢复（B 类，逐步授权）

在 APP_HOST 的交互会话中执行，`$D` 同第 2 步。如果 0.3 记下了主机上已占用的 PG 端口（例如 5432），用 `--running-port` 传入：

```
date -u +%FT%TZ
sudo -u nexloop-pgbackrest /opt/nexloop/restore-venv/bin/nexloop-restore \
  --source pgbackrest --pgbackrest-bin /usr/bin/pgbackrest --pgbackrest-config-file "$D/conf/pgbackrest-drill.conf" \
  --stanza nexloop --repo 1 --target-name drill-<DRILL_ID> --drill-mark-file "$D/conf/mark-<DRILL_ID>.json" \
  --pg-bin /usr/lib/postgresql/18/bin --pg-path "$D/pgdata" --port <DRILL_PORT> --socket-dir "$D/socket" \
  --owner-user nexloop_bootstrap --hba-method trust --restore-ref drill-<DRILL_ID> --journal-dir "$D/journal" \
  --old-primary-fenced --running-port 5432 --report-file "$D/report/restore-<DRILL_ID>.json" --stop
date -u +%FT%TZ
```

代码依次执行：

1. 拒绝非空的 pgdata 或已占用的端口；
2. `pgbackrest restore`，类型为 name，目标恢复点 `drill-<DRILL_ID>`，`--target-action=promote --archive-mode=off`；
3. 写 `postgresql.auto.conf`：`listen_addresses=''`、本次端口、socket 目录、`archive_mode=off`；pg_hba 只有 `local all nexloop_bootstrap trust`；
4. 启动实例并等它退出恢复状态（最多 300 秒）；
5. 把其他 `nexloop_*` 角色都设为 NOLOGIN；
6. `nexloop_restore_begin`（恢复围栏），重放恢复日志，`nexloop_restore_reconcile`（没有证据文件，所以每个渠道都暂停）；
7. 核对 lineage；
8. `nexloop_restore_verified`，进入 `verified_readonly`；
9. 与标记比对，并检查五条补偿控制；
10. 写报告（新文件，0600）；
11. `--stop` 停止实例。

`--old-primary-fenced` 在这里的含义：生产库不受影响，演练实例从不向 stanza 归档（配置中没有 archive-push，且 `archive_mode=off`）。真实灾难恢复时，必须先隔离原主库，才能加这个参数。

**预期**（标准输出与 `$D/report/restore-<DRILL_ID>.json` 相同，退出码 0）：

| 字段 | 预期 |
|---|---|
| `passed` | `true` |
| `state` | `verified_readonly` |
| `instance` | `stopped` |
| `checks.controls` | 五项全部为 `true` |
| `checks.drill_compare` | `count_mismatches` 为 0，`sample_mismatches` 为 0，`catalog_equal` 为 `true` |
| `lineage` | `revision` 为 `0197` |
| `journal_entries` | 0（本次日志为空） |
| `roles_set_nologin` | 应用角色数（大于 0） |
| `tool_seconds` | 从开始 `pgbackrest restore` 到 `verified_readonly` 的秒数，即本次 **RTO**，门槛 ≤ 7200（D2） |

**失败时**：标准输出为 `{"passed": false, "refused": "…"}` 或 `{"passed": false, "error": "…"}`，退出码 1；出错时代码会先停止实例。依次查看 `$D/pgdata/restore.log` 和 `$D/log`。不要在原目录上重试：按第 8 步销毁后，用新的 `<DRILL_ID>` 从第 2 步重来（第 1、3 步的 venv 和配置可以保留到最后）。

## 7. 记录到 `runtime.nexloop_restore_drills`（B 类；DATA_HOST sudo 由负责人）

- drill 行本身已在第 4 步由 `drill-mark` 写入；
- 结果由 recorder 调用 `authz.nexloop_record_drill_result` 写入 `runtime.nexloop_restore_drill_results`。该函数只接受 `passed` 或 `failed`、非负的 RTO 与 RPO，以及以小写代码为键、值为布尔或数字的检查项；
- 没有命令行入口，用 backup-venv 的 Python 调用 `backup.record_drill_result`。

先按第 4 步的方式，把报告从 APP_HOST 经负责人中转到 DATA_HOST 的 `/srv/nexloop/backups/file-repo1/drill-<DRILL_ID>/restore-<DRILL_ID>.json`（`sudo install -o nexloop-backup -g nexloop-backup -m 0600`）。然后在 DATA_HOST 上由负责人执行，`<RPO_SECONDS>` 取第 4 步算出的值：

```
sudo -u nexloop-backup /opt/nexloop/backup-venv/bin/python - /srv/nexloop/backups/file-repo1/drill-<DRILL_ID>/restore-<DRILL_ID>.json <DRILL_ID> <RPO_SECONDS> <<'PY'
import json, sys
from nexloop_eios.backup import record_drill_result
from nexloop_eios.private_configuration import read_private_text
report = json.loads(read_private_text(sys.argv[1], maximum=1048576))
compare = report['checks']['drill_compare'] or {}
