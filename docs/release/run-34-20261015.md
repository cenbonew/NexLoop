## 1. 合成租户与服务主体（DATA_HOST 一次性容器，B）

### 1.1 入口结论

- **建租户没有独立入口。** 0050 `control.nexloop_configure_manifest` 在第一次受信配置发布时插入 `control.nexloop_tenants(tenant_id, status)`（`0050_trusted_configuration.sql`，约第 89 行；后续迁移重定义时保留）。`service_grants.apply` 发布时用 `tenant_status = 'active'`（`service_grants.py:apply`）。
- 因此 **register 的第一次执行就建立了租户**，同时建立 21 个服务主体、凭据和授权，以及 relay Source 的 `message_read_rule`。
- 不用 `scripts/nx037/real_tenant_init.py`，原因有两个：
  - 它只有 `plan|execute|verify` 三种模式，没有合成模式；
  - 它要求 `--configurator-dsn-file`，没有登录窗口方式，而且它的授权只是 `service-grants.v1.json` 的子集。
- 它的第 2、3 步 `effect_categories.apply`、`observability.apply_rules` 留给 3.4 之后（缺口 G2）。
- `enterprise_setup`、`business_setup`、`catalog_setup` 都在租户存在之后，以服务凭据经 API 运行，不建租户。

### 1.2 `--tenant` 取值

- 取一个新生成的小写 UUID：`python3 -c 'import uuid; print(uuid.uuid4())'`。`real_tenant_init.py:parameters` 也要求 UUID 形式，并拒绝沙箱租户 `sandbox_profile.SANDBOX_TENANT`；后续 NX-037 工具沿用这个租户，所以此处一并满足。
- 记为 `$TENANT_ID`，写进私有记录，并在第 4 步作为 `BROWSER_TENANT_ID`。
- 合成租户的含义是：只放合成数据，真实派发关闭。它在库里是普通租户，“合成”靠 D9 和后续数据约束保证。

### 1.3 源码树（register 脚本与清单）

发布镜像（backend `2d76f3db…`）只含 wheel，不含 `scripts/deploy` 和 `deploy/authorization`。register 需要的 `--bootstrap-dsn-file` 和按主体发令牌的改动在 main（9bc71a7）里，不在 76df192 里，所以：

- 脚本与清单取 main 9bc71a7：
  ```
  git archive 9bc71a7 scripts/deploy/stage_secrets.py scripts/deploy/issue_certs.py deploy/authorization | tar -x -C "$REG_SRC"
  ```
  另需 `deploy/stage/compose.app.example.yaml` 与 `compose.data.example.yaml`：脚本模块级常量引用它们，register 不读取。
- Python 包仍用发布镜像里的 wheel：
  - `stage_secrets.py` 会把 `<源码树>/packages/eios-core/src` 插到 `sys.path` 前面，而上面的归档不含 `packages/`，所以导入的就是镜像里的 wheel；
  - 核对：容器内 `python -c 'import nexloop_eios,sys;print(nexloop_eios.__file__)'` 应在 site-packages 下。
- 风险说明：register 依赖 76df192 wheel 里的 `service_grants` 与 `trusted_configuration`。这两个文件在 76df192 与 9bc71a7 之间，以 `git diff 76df192 9bc71a7 -- packages/eios-core/src/nexloop_eios/service_grants.py packages/eios-core/src/nexloop_eios/trusted_configuration.py` 核对。执行前必须为空；不为空就停下报告。2026-10-15 在 CI 主机已核对：两个文件的差异为空，`eios/migrations` 也没有变化。

### 1.5 命令

`$BACKEND_IMAGE` 写 `nexloop/backend@sha256:2d76f3db…`（取发布清单的完整 digest）。

```
COMMON="--rm --network none --read-only --user 999:999 --cap-drop ALL --security-opt no-new-privileges --tmpfs /tmp:rw,noexec,nosuid,size=16m \
  -v $RUN/src:/opt/release:ro -v $RUN:/stage:ro --entrypoint python"
# 1) dry-run：只列出主体、授权与 message_read_rule
docker run $COMMON "$BACKEND_IMAGE" /opt/release/scripts/deploy/stage_secrets.py register --out /stage --tenant "$TENANT_ID" --dry-run
# 2) 正式执行（B）
docker run $COMMON -v "$NEXLOOP_ROOT/run/postgresql:/var/run/postgresql" -v "$RUN/boot.dsn:/run/bootstrap-dsn:ro" \
  "$BACKEND_IMAGE" /opt/release/scripts/deploy/stage_secrets.py register --out /stage --tenant "$TENANT_ID" \
  --bootstrap-dsn-file /run/bootstrap-dsn --signing-key-id nexloop-stage-20261014 --credential-expires-at "$CREDENTIAL_EXPIRES_AT"
# 3) 再执行一次（幂等核对），命令同 2)
```

说明：`--out /stage` 让脚本读 `/stage/management/…`。挂载根 `$RUN` 只读，临时文件只写在 tmpfs 里。

**预期**：
- dry-run：`principals` 21 个、`grants` 61 条、`credential_files` 28 个、`message_read_rules: ["relay_source"]`。
- 正式执行：
  - `changed: true`，`credentials_created` 21 个，`message_read_rules_written: 1`；
  - `grants_revoked: 0`，`extra_grants_outside_manifest: 0`。
- 再执行一次：`changed: false`。
- 输出不含任何令牌。

**核对**（bootstrap socket，只读）：
- `select tenant_id,status from control.nexloop_tenants`：只有 `$TENANT_ID`，状态为 `active`。
- `select distinct operator_role from control.nexloop_configuration_publications`：只有 `nexloop_configurator`。
- `select rolcanlogin, rolpassword is null from pg_authid where rolname='nexloop_configurator'`：返回 `(f, t)`。
- `select count(*) from authz.nexloop_service_credentials`：21。

**撤销**：
- 不删表。若要作废，按 service_grants 清单撤销授权（`retired`），或把凭据 `status` 改为 `revoked`，都经受信配置。
- 删除 `$RUN`：`shred -u $RUN/boot.dsn $RUN/management/*`，然后 `rm -r $RUN`。

**注意**：
- `signing.key.hex` 与 `--signing-key-id` 要和 APP_HOST 的 `shared/signing.key`、`SIGNING_KEY_ID` 同源，都取自 `secrets-20261014` 这一棵树。
- effect_executor 的令牌必须就是 owner 做 `configure_effect_control` 时使用的执行者令牌（缺口 G3）。
