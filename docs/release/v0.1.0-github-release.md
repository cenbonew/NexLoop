## NexLoop v0.1.0

**English** · [简体中文](#简体中文)

NexLoop is an open-source continuous-operations system for enterprises. **v0.1.0 is its first open-source release: the controlled real closed loop.** That means one tenant, one real interaction channel (native WebChat), one real delivery action and one controlled real model. Reliable real-world actions come before consumer digital twins and simulated strategy selection. The project is exploratory: it does not promise more revenue, and interfaces will still change.

**Main capabilities**

- Governed EIOS Actions are the only way to change formal business objects or cause external effects. Business-intent IDs are stable; state is persisted before ACK; an unknown outcome is queried and reconciled before anything else happens. Real dispatch has a three-layer switch.
- Conversations become ontology: Claim extraction with source spans, hybrid and vector recall, matching, and candidate definitions under human review.
- Goals, plans and context with per-source authorization; customer protection (a hard stop on "do not contact me", a guaranteed reply); commitments, commercial events and incentives.
- An owner workbench with role-based governed actions, human takeover and audit; retention, erasure with restore-time replay, and governed export.
- Operations: metrics and alerts, backup and point-in-time restore with a restore fence, a migration gate without waivers, signed releases, and a local Git queue with an isolated CI.

**Acceptance**: S1–S5, 68 acceptance tests, all passed. Stage S5 was accepted on a real two-host stage running the final acceptance release 22 (`20261019-47aa87b898f2-1`, commit `47aa87b8`), including a controlled trial of 36/36 interactions with a real model and real deliveries. Details and evidence levels are in the [release notes](https://github.com/<OWNER>/<REPO>/blob/v0.1.0/docs/release/v0.1.0-release-notes.md). Public pre-flight: 【待 preflight】.

### 简体中文

NexLoop 是面向企业的开源持续运营系统。**v0.1.0 是它的首个开源版本：受控真实闭环。** 也就是一个租户、一种真实交互渠道（原生 WebChat）、一项真实交付动作、一个受控真实模型。真实动作的可靠性优先于消费者数字孪生和模拟选优。项目仍在探索阶段，不保证提高收入，接口还会变化。

**主要能力**

- 只有受治理的 EIOS Action 能改正式业务对象或产生外部效应。业务意图 ID 稳定；先持久化再 ACK；结果不明时先查询对账，再决定下一步。真实派发有三层开关。
- 对话到本体：带原文区间的 Claim 提取、混合召回与向量召回、匹配，以及经人工审核的候选定义。
- 按来源授权的目标、计划与上下文；客户保护（“别再联系我”硬性停发、来信必有回复）；承诺、商业事件与优惠。
- 负责人工作台：按角色的受治理操作、人工接管与审计；数据保留、删除及恢复后重放、受治理导出。
- 运维：指标与告警，备份与按时间点恢复（带恢复围栏），无豁免的迁移门槛，签名发布，本地 Git 队列与隔离的 CI。

**验收**：S1–S5 共 68 项验收全部通过。S5 是在真实的两机 stage 上、用最终验收发布 22（`20261019-47aa87b898f2-1`，commit `47aa87b8`）完成的，其中包括 36/36 次使用真实模型与真实交付的受控试运行。详细结果与证据等级见[发布说明](https://github.com/<OWNER>/<REPO>/blob/v0.1.0/docs/release/v0.1.0-release-notes.zh-CN.md)。公开发布预检：【待 preflight】。
