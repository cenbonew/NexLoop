# ADR-033（草稿）｜负责人确认外部效应未发生

状态：**草稿**，待负责人确认。编号按 adr/ 下的顺序暂定为 033，合入时以实际顺序为准。
关联：AGENTS（结果不明不能盲目重试，要先查询、再对账）；ADR-023（回复保证）；0042（效应账本）；0079（出站记录）；0152（回复对账）；0174/0199（停止自动重查）；0205（负责人下单重查）；设计稿 `docs/design/confirm-effect-not-delivered.md`。

## 1. 背景

效应结果不明（unknown）时，系统只能通过 provider 查询来收敛。当来源 Run 已过期、provider 也查不到记录（not_found）时，按现有规则这条意图永远停在 unknown：
- 不会重发，这是正确的；
- 但也没有任何受治理的方式把它收尾，告警 `unknown_over_24h` 会一直存在。

not_found 不能证明效应没有发生，provider 可能已经删除了旧记录，因此不能由系统自动判定。

## 2. 决定（草案）

1. **只有人类负责人能判定。** 新增受治理 Action `nexloop.effect.confirm_not_delivered`（版本 1）。SQL 只接受人类负责人身份，服务、Agent、Run 凭据一律拒绝。每次判定都要带确认引用和理由。
2. **前置条件：**
   - 意图处于 unknown；
   - 有受治理查询留下的 not_found 观测作为证据，它是最新的一条，且晚于最后一次 attempt；
   - 已过最小等待期，由可配置策略决定，默认首次 unknown 后 24 小时、not_found 后 10 分钟；
   - 派发控制放行；
   - 这条意图尚未被判定过。
3. **效果：**
   - 在同一事务里，意图、outbox、attempt 转为终态 `failed`，出站记录 unknown → failed；
   - 写一条只追加的判定记录 `confirmed_not_delivered`，内容包括依据的观测、确认引用、理由、负责人、时间，以及回复跟进方式；
   - 不发送任何东西，不新建意图，不重发；
   - 指标中的 unknown 计数随之下降。
4. **回复保证：** 判定时选择对这条消息的跟进方式：
   - 默认为“负责人跟进”：回复保证项以 `owner_follow_up` 升级结清，不自动兜底；
   - 也可以按条选择“允许一次兜底回复”。
   - 一条消息最多一次兜底回复（ADR-023），这一点不变。
5. **审计：** 判定记录、出站转移事件、原有 not_found 观测共同构成证据链；工作台和 nx037 只读取 id、类型、时间和引用。

## 3. 后果

- 存量 unknown 有了受治理的收尾方式，告警可以恢复。
- 如果原效应其实已经发生（provider 只是丢了记录），系统账本会把它记为未送达。这个风险由负责人在判定时承担，并且有证据可查；默认的回复跟进方式（负责人跟进）避免了因此自动重复回复。
- 不新增意图状态（推荐方案），已有的终态判断代码都不需要修改。

## 4. 待确认
