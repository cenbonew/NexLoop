## 0. 一页结论

- **要接入的是什么**：企业自己的程序或 Agent（不是 NexLoop 的 Pi Run，也不是消费者渠道），在治理范围内读取世界模型、调用受治理 Action。形态有四种：API key（F1）、MCP、网关（F1）、Python SDK 与 CLI（F2）、技能包（F3）。F2、F3 都只是 F1 的客户端，不新增服务端能力。
- **核心原则**：
  1. 机器调用方是租户下登记的**服务主体**，不是人，也不代表任何人（不做委托，Q5、ADR-033）；
  2. 它能做的事是三者的**合取**：密钥的 scope ∩ 主体的服务授权 ∩ 能力当前的策略（含 NX-056 审批）；在**派发时**检查，不只在网关检查；
  3. 它只能经 C8 清单中逐条登记为 `machine_key` 的路由进入，只能到达**受治理 Action 与已登记的读取动词**；不能做审批决定、密钥签发、成员与授权管理、发布、擦除决定和真实派发开关；
  4. 租户、world、actor 一律从凭据推出，请求体中出现这些字段返回 422；
  5. 写请求必须带业务意图 ID（幂等键），同键不同内容返回 409；unknown 结果先查询，不盲目重试；
  6. 模型输出不能直接当动作参数（Q7）：服务端把机器请求当作不可信输入，按能力的参数 Schema 校验；有外部效应或高风险的能力必须经审批策略，由人决定。
- **最大的三项风险**与缓解：密钥泄露（短有效期、只存摘要、双密钥轮换、立即吊销、按密钥限速与预算、world 绑定）；越权到达非治理端点（C8 的 `machine_key` 精确集合 + G-5 式无凭据/错 realm 探测）；模型输出驱动外部效应（审批策略 + 二次确认摘要 + 第一期不开放外部效应能力）。
- **第一期建议范围**（ADR-041 Q-1）：只读动词 + 无外部效应的受治理 Action；外部效应能力放到第二期，并强制审批策略。

## 3. 信任边界

```
企业的程序 / Agent（不可信：可能被提示注入、可能有缺陷、密钥可能泄露）
   │  TLS，Authorization: Bearer <机器密钥>
   ▼
B1  Gateway（Caddy）：只转发清单中的路径；删除调用方带来的身份类请求头；/internal/* 404
   ▼
B2  nexloop-api：realm 判定（machine_key 只匹配登记的路由）→ 密钥校验（摘要比对、有效期、吊销、world）
   → 请求形状校验（无 tenant/actor/world 字段，参数 Schema，幂等键）→ 限速与预算
   ▼
B3  PostgreSQL 受治理入口（SQL）：按当前事实检查 scope ∩ 服务授权 ∩ 能力策略（审批）→ Action
   ▼
B4  派发：联系限制、真实派发开关、world 再检查（与人类路径相同，机器路径不另开）
```

- B1 不是授权边界，只是减少暴露面；**所有授权判定在 B2、B3**，B3 是最终判定。
- 机器调用方与 NexLoop 自己的 Pi Run 是两条不同的入口：Pi Run 的凭据由 Agent Host 按 Run 签发；机器密钥由负责人签发、长期（有上限）存在。两者不能互换（§5 T-5）。

## 5. 威胁、缓解与测试

每条威胁给出：攻击方式 → 缓解（设计要求）→ 实施时的测试。T 编号供 ADR-041 引用。

### T-1 密钥泄露（客户端日志、仓库、技能包、CI 变量）

- **攻击**：拿到密钥的人在有效期内以该主体的全部 scope 调用。
- **缓解**：
  1. 密钥只在签发时显示一次；服务端只存 HMAC-SHA256 摘要（服务端密钥来自私有配置）和一个非秘密的前缀 ID，用于审计与吊销定位；
  2. 必须有有效期，上限 90 天（Q-2）；没有“永不过期”；
  3. 密钥绑定**一个租户、一个 world**；test/sim 的密钥无法在 real world 认证（与 Run 的 world 规则一致）；
  4. 按密钥限速与日预算（T-8），把泄露后的损害限制在一个窗口内；
  5. 可选的来源网段白名单（默认关，Q-8）；
  6. 客户端（SDK、CLI、MCP、技能包）只从私有文件（0600、本人所有）或环境变量引用读取密钥，不接受命令行参数，不打印；仓库发布前扫描（`prepush-scan.sh`、gitleaks）增加机器密钥前缀的规则；
  7. 异常检测：同一密钥短时间内大量拒绝（scope 外、Schema 不符）触发告警，负责人可一键吊销；告警阈值在实施时写进告警规则的新版本（与现有告警规则同样受审、版本化），不写死在代码里；
  8. 服务端 HMAC pepper（摘要密钥）来自私有配置，支持轮换：过渡期内同时持有新旧两个 pepper，校验时按密钥记录的 pepper 版本选用，新签发与轮换后的密钥只用新 pepper，旧 pepper 在其下最后一把密钥过期或重签后撤下；pepper 纳入备份（与审计链封印密钥同样的私有备份路径）。**pepper 丢失会让所有机器密钥失效**，恢复演练要覆盖这一项。
- **测试**：
  - 数据库中查不到明文密钥（全表扫描签发后的明文不出现）；
  - 过期、吊销后的第一个请求即 401；
  - test world 密钥访问 real world 资源 401；
  - SDK/CLI 在日志、异常、`--help` 输出中不含密钥（用不像十六进制的标记值断言不出现）；
  - gitleaks 规则能命中一个合成的机器密钥；
  - pepper 轮换：旧 pepper 下签发的密钥在过渡期内仍可认证，撤下旧 pepper 后 401；新签发的密钥只用新 pepper；
  - 告警规则清单中有机器密钥拒绝率规则，阈值来自规则版本而不是代码常量。

### T-2 密钥轮换窗口与吊销不及时

- **攻击**：轮换时新旧密钥同时有效太久；吊销后缓存仍放行。
- **缓解**：
  1. 每个主体最多两把有效密钥（轮换重叠），重叠期上限 7 天（Q-2）；
  2. 吊销立即生效：每次请求在 B3 按**当前事实**检查密钥状态，不在 Valkey 或进程内缓存“有效”结论（Valkey 只能缓存“已吊销”的负结果）；
  3. 签发、轮换、吊销都是受治理 Action，执行者为负责人（Q-4），留审计并进链；
  4. **机器主体停用时，它名下的全部密钥级联失效**：停用与吊销在同一事务里完成，认证检查同时要求密钥有效且主体处于启用状态（两层都查，任何一层失效即拒绝）。
- **测试**：吊销后同一连接上的下一个请求 401；第三把密钥签发被拒；吊销在另一个 API 进程上立即可见（两进程测试）；停用机器主体后，它名下两把密钥都 401，且密钥行状态均为已吊销（级联），重新启用主体不会让旧密钥复活。

### T-3 越权调用非治理端点或管理能力

- **攻击**：用机器密钥访问工作台、消费者、`pre_session`、`/internal/*`、或带 `Authorization` 头去打 cookie 会话路由，期望某处漏检；或者调用审批决定、密钥签发、授权与成员管理。
- **缓解**：
  1. C8 清单新增 realm `machine_key`，**只能**用于逐条登记的路由；G-2 的精确集合同样适用，新增一条机器路由必须同时改清单和测试中写死的集合（两处同时修改）；
  2. realm 互斥：机器密钥在 cookie 会话路由上一律 401（不尝试“兼容”），cookie 会话在 `machine_key` 路由上一律 401；
  3. 机器主体的服务授权只能包含受治理能力与已登记的读取动词；以下能力**永不**授予机器主体，由 SQL 侧拒绝并由清单检查锁定：审批决定、密钥与服务授权管理、成员与角色、发布（Schema、策略、规则、关系类型）、擦除与保留决定、真实派发开关、补救的人工决定；
  4. 工作台写入口 `actions/{operation}` 不对机器开放；机器路由按能力逐条登记，不提供“通用分发”。
- **测试**：
  - 扩展 G-5：对每条非 `machine_key` 路由带一个有效机器密钥请求，必须 401/403；对每条 `machine_key` 路由不带凭据、带 cookie 会话、带 Run 令牌，都必须 401；
  - **矩阵为空即失败**：G-5 扩展的探测矩阵（路由 × 凭据种类）在运行前先断言行数大于 0，并且等于清单路由数 × 凭据种类数；清单未加载、过滤后为空或某种凭据夹具缺失时，门禁失败，不能静默通过；
  - 清单检查：`machine_key` 路由引用的能力与“永不授予”集合不相交；
  - 真实 PG：给机器主体手工插入一条审批决定的授予（模拟配置错误），SQL 仍拒绝。

### T-4 模型输出直接当动作参数（Q7）

- **攻击**：企业的 Agent 被提示注入（例如消费者消息里的文字），把注入内容原样作为 Action 参数（收件人、金额、正文、对象 ID），或连续调用造成批量外发。
- **缓解**：
  1. 服务端不信任机器请求的任何参数：每个机器可调用的能力都要有**参数 Schema**（类型、枚举、长度、ID 形状），未知字段拒绝；ID 类参数必须指向调用方 scope 内可见的对象，否则 404（不泄露存在性）；
  2. **第一期不开放外部效应能力**（Q-1）；第二期开放时，这些能力必须配置 NX-056 审批策略：机器主体只能是请求人，不能是审批人，也不计入法定人数（Q-6）；
  3. **二次确认摘要**：有副作用的 Action 分两步，`prepare` 返回规范化参数与摘要，`commit` 必须带回同一摘要（与审批的 request_digest 同一做法）；这让调用方的人或程序有机会看见“实际要执行的参数”，也阻止参数在两步之间被替换；
  4. 联系限制、勿扰与频率上限、真实派发开关在派发时照常检查（B4），机器路径不另开；
  5. NexLoop 自己的 Agent Host 另行加入静态数据流检查（Q7 的吸收部分），与本通道独立。
- **测试**：
  - 未知字段、超长、错误形状的参数 422；
  - 指向他人或不存在对象的 ID 返回 404 且响应不区分两者；
  - `commit` 摘要不一致 409；
  - 有外部效应的能力在没有审批策略时，机器主体调用被拒（`approval_policy_required`）；
  - 机器主体对自己的请求投票被拒，且不计入法定人数。

### T-5 租户、world、主体串号

- **攻击**：请求体或头里带别的 `tenant_id`、`world`、`actor`；用 Run 令牌或渠道凭据冒充机器主体，或反过来。
- **缓解**：
  1. 租户、world、actor 只从凭据推出；请求体、查询串出现 `tenant_id`、`world`、`actor`、`principal_id`、`on_behalf_of` 等字段返回 422（与 ADR-033 §2.5 一致）；
  2. 应用不读任何身份类请求头；Gateway 删除这些头（防御纵深）；
  3. 三类服务凭据（Run 令牌、渠道凭据、机器密钥）用不同的前缀与不同的认证绑定类型，校验函数按 realm 只接受一种；
  4. SQL 侧所有读写按凭据推出的租户与 world 过滤；读取复用已有的租户 FK 与行级安全。
- **测试**：
  - 带 `tenant_id` 的请求 422；
  - 租户 A 的密钥读租户 B 的对象 404；
  - Run 令牌、渠道凭据在 `machine_key` 路由 401，机器密钥在 Run 与渠道入口 401；
  - 伪造 `X-NexLoop-Principal` 头不改变审计中的 actor。

### T-6 重放与重复执行

- **攻击**：截获或重发一次写请求；客户端超时后盲目重试导致重复外发。
- **缓解**：
  1. 只允许 TLS；HSTS 已由 Gateway 负责；
  2. 每个写请求必须带业务意图 ID（幂等键，客户端生成，稳定跨重试）；同一主体同一意图 ID：内容相同返回首次结果，内容不同 409；持久化在 PG，先持久化后 ACK；
  3. 外部效应结果为 unknown 时，返回 unknown 和查询入口，SDK 的默认行为是查询，不是重发（AGENTS.md：unknown 不是失败）；
  4. 第一期用 Bearer + TLS + 幂等键；请求签名（HMAC，带时间戳与 nonce）作为第二期选项（Q-3）。
- **测试**：同一意图 ID 重发得到同一结果且只有一条 Action 记录；同 ID 不同内容 409；服务重启后重发仍去重；SDK 在 unknown 时调用查询而不是重发（客户端单测）。

### T-7 审批绕过与自批

- **攻击**：机器主体同时持有请求与决定能力，自己批自己；或把需要审批的能力拆成多次小请求。
- **缓解**：审批决定永不授予机器主体（T-3）；审批策略按能力生效，与请求来源无关；批量与拆分由 T-8 的动作预算与审批策略的阈值共同约束。
- **测试**：机器主体调用审批决定入口 403；同一能力在有策略时，机器请求进入待审批，未批前不执行。

### T-8 速率、预算与资源耗尽

- **攻击**：泄露的密钥或有缺陷的 Agent 高频调用，耗尽 PG 连接、模型预算或外发配额。
- **缓解**：
  1. 按密钥与按租户两级限速，持久在 PG（与 `browser_rate_limits` 同一做法：HMAC 键、服务端绑定，不以客户端 IP 为唯一键，因为 stage 的反代会去掉转发头）；
  2. 按密钥的日动作预算，按能力可配；超出返回 429 与 `Retry-After`；
  3. 读取有分页上限与单次返回上限；
  4. 机器调用触发的 Run（如果有）仍受现有三层预算约束，不另开预算；
  5. 连接池：机器路由使用独立的并发上限，避免挤占工作台与消费者。
- **测试**：超过限速 429 且带 `Retry-After`；预算耗尽后到次日窗口恢复；并发上限下工作台读取仍可用（负载测试，-n 受本地限制，放到 CI 主机）。

### T-9 审计归属不清

- **攻击**：事后无法区分是人、Pi Run、渠道还是企业程序做的；或者审计被删改。
- **缓解**：
  1. 审计记录 actor 为机器主体，另记密钥前缀 ID、意图 ID、trace_id、能力、结果码；不记密钥、不记正文；
  2. 不存在 `on_behalf_of` 人类（不做委托，Q5）；机器主体的显示名与负责人登记的用途一起显示在工作台；
  3. 机器调用写入 `runtime.audit_events`，因此自动进入 NX-059 哈希链；密钥签发、轮换、吊销同样进链；
  4. 工作台按主体、按密钥查询审计（只读）。
- **测试**：一次机器 Action 后，审计中 actor、密钥前缀、意图 ID 正确，且该行进入哈希链并能通过带密钥校验；审计正文与日志中不出现密钥（不像十六进制的标记值断言）。

### T-10 MCP 与技能包的供应链和配置

- **攻击**：技能包写死某个部署地址；MCP 客户端把密钥写进配置文件被同步到公开仓库；恶意 MCP 工具描述诱导 Agent 调用高风险工具。
- **缓解**：
  1. MCP 客户端只在本地 stdio 运行，经 HTTP API，工具集合等于该密钥 scope 内的 `machine_key` 路由（不多给）；不提供审批、密钥管理类工具；
  2. 工具描述由服务端清单生成，不接受客户端注入；有副作用的工具标明“需要确认”并实现 T-4 的两步；
  3. 技能包与 SDK 的地址、CA 文件都是配置项，不含任何部署地址；发布前跑 `check_publication`；
  4. 第三方依赖按 `versions.lock.json` 与许可证策略管理。
- **测试**：MCP 工具列表等于 scope 内路由；技能包构建产物中没有地址字面量；公开扫描通过。

### T-11 信息泄露（错误、计时、存在性）

- **攻击**：通过错误信息、状态码差异、响应时间判断对象是否存在或密钥前缀是否有效。
- **缓解**：不存在与无权限统一 404；认证失败统一 401 且正文只有错误码；密钥摘要比较用常量时间；错误响应不回显参数值。
- **测试**：同一请求对“存在但不可见”和“不存在”的对象，状态码与正文相同；错误响应不包含请求中的参数值。

### T-12 消费者个人数据的读取面

- **攻击**：机器主体（或拿到其密钥的人）经读取动词批量拉取会话正文、联系方式等消费者个人数据；或者读到已擦除、已过保留期的数据。读取面比写入面更容易被忽视，因为读取没有外部效应，却直接构成泄露。
- **缓解**：
  1. **默认不返回会话正文和联系方式**。机器可用的读取动词按能力逐条登记**字段投影**：登记的是“这个读取对机器返回哪些字段”，未登记的字段一律不返回；会话正文、消息正文、联系方式（手机号、邮箱、外部账号引用）、自由文本备注默认不在任何投影里。需要时由负责人按能力逐条决定是否加入投影（ADR-041 Q-9），决定留审计、投影随清单版本化；
  2. **遵守擦除与保留状态**：机器读取与工作台读取走同一套判定，即 NX-054 的统一擦除判定（已擦除值、假名、擦除请求标记一律视为已擦除）与保留状态（到期清理、legal hold）；不为机器读取另写一份判定，已擦除或已清理的对象对机器返回 404 或已擦除占位，与人类读取一致；
  3. 读取有分页与单次返回上限（T-8），按密钥审计读取（按天计数，与 `nexloop_workbench_read_audit` 同一口径）；
  4. 投影在服务端（SQL 读取函数）执行，不在应用层过滤后返回，避免新增字段时漏过滤。
- **测试**：
  - 对每个机器读取动词，返回字段集合精确等于登记的投影（新增字段而不登记，测试失败）；
  - 默认投影不含正文、联系方式字段（逐字段断言，使用不像十六进制的标记值确认不出现）；
  - 对已擦除的消费者，机器读取的结果与工作台读取一致（404 或已擦除占位），且不出现擦除前的值；
  - 处于 legal hold 或已过保留期的数据，机器读取的结果与工作台读取一致；
  - 读取审计按密钥按天计数正确。

## 6. 剩余风险

| # | 风险 | 为什么接受 / 何时再评 |
|---|---|---|
| R-1 | 有效期内的泄露密钥在被发现前可用 | 有效期上限、限速、预算、告警与立即吊销把窗口限制住；请求签名（Q-3）在第二期再评 |
| R-2 | 企业 Agent 在 scope 内做“合法但错误”的事 | 这是企业自己的 Agent 的责任；第一期无外部效应能力，第二期有审批 |
| R-3 | 读取面扩大 | 见 T-12：默认投影不含正文与联系方式，按能力逐条登记字段投影，遵守擦除与保留；第一期只开放清单中逐条审定的读取动词；按密钥审计读取（按天计数） |
| R-4 | 负责人是唯一的密钥签发人，负责人账号被攻破则全部失守 | 与现有负责人操作同一风险等级；工作台登录与口令重置已有限速和审计；OIDC（C4）后再评 |

## 7. 不做

- 不做委托（机器代表某个人执行）和紧急提权（Q5、ADR-033）；
- 不做托管的远程 MCP 服务（Q-5 推荐），不做上游那样的独立 Agent 网关进程；
- 不做出站 webhook；
- 不开放工作台写入口的通用分发；
- 不让机器主体创建消费者、成员或其他主体；
- 不做 OAuth 第三方授权（第三方应用代表企业）；如有需求另行评审。
