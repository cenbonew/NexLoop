# 消费者通道 API（第 2 期）：负责人拍板单

依据：[消费者通道 API 设计稿](consumer-channel-api.md) §10。每项都列出选项、推荐与理由，以及选定后的工作量。工作量是开发线的估计，单位“人日”，含测试与文档，不含排队与 CI 等待；需要 ADR 的项会单独注明。

**结论先看**：如果全部按推荐，第 2 期约 **13–15 人日**：其中基础部分约 3.5–4 人日（与选项无关，包括渠道路由与端点、消费者绑定 Action、请求审计以及与 WebChat 一致性的真实 PG 测试），D1–D7 的推荐项合计约 9.5–10.5 人日。需要 **2 份 ADR**（D2 代表关系、D5 测试人设标记），建议排在 v0.1 验收之后（D6）。v0.1 期间，Codex 继续用已经合入的第 1 期（CLI、MCP）。

| # | 要决定的事 | 选项 | 推荐 | 理由 | 选定后的工作量 |
|---|---|---|---|---|---|
| **D1** | 渠道凭据用什么形式 | **A. 签名 bearer 令牌**：渠道是一个服务主体，凭据放在私有文件里，经受治理的 Action 签发与吊销<br>B. mTLS 客户端证书：由 NexLoop CA 签发，按证书 CN 识别渠道 | **A** | 复用现有的服务主体凭据与吊销机制，轮换简单。stage 现在没有外部合作方，用不上 mTLS 的强身份。等将来对外开放给合作方时，再加 B 作为可选项 | A：2 人日（签发、验证、吊销、轮换并存与测试）<br>B：4 人日（另需 Gateway 透传证书、CN 映射与轮换流程） |
| **D2** | 以谁的身份执行受治理的消息 Action | **A. 渠道服务主体“代表消费者”执行**：授权事实中新增一条代表关系，审计记录渠道与消费者两方<br>B. 每个绑定签发一个消费者范围的短期令牌，渠道持令牌，以消费者身份执行 | **A** | 只有一个执行主体，审计清楚，吊销绑定就能立刻生效。B 要管理大量短期令牌及其续期，还要在渠道侧保存它们，泄露面更大 | A：3–4 人日，**需要 ADR**（授权模型里加入“代表消费者”的事实，属于契约改动）<br>B：4–5 人日（令牌签发、续期与存储，同样需要 ADR） |
| **D3** | 默认限流与配额 | A. 测试渠道：每个消费者每分钟 10 条，每个渠道每分钟 120 条；正式渠道按合作方另定<br>B. 先不限流，只记录 | **A** | 限流是防止误用和失控循环的第一道闸，例如代理死循环地发消息；测试渠道的这组数足够 Codex 模拟顾客。B 会让一个出错的代理直接打满预算 | A：1.5 人日（两层计数器，复用浏览器登录限流的实现）<br>B：0.5 人日 |
| **D4** | 首版是否提供回复 webhook | **A. 首版不提供**：只用轮询或 SSE 读回复<br>B. 首版提供：回复写入后推送签名事件 | **A** | webhook 向外推送，属于外部效应：要走效应路径、三层真实派发开关、联系限制与重试对账，工作量和风险都明显更大。测试驱动用轮询或 SSE 已经够用 | A：0（轮询与 SSE 已含在端点里）<br>B：4–5 人日（另立任务：效应 Action、开关、签名、重试与对账） |
| **D5** | 测试人设怎么标记 | **A. 在系统内标记**：消费者绑定带 `persona`（如 `simulated_agent`），分析、Claim 与报表可以按它排除<br>B. 只在证据中标记（现状：NX-037 的 participants 清单） | **A** | 渠道 API 打开后，测试流量会长期存在。只在证据里标记，后续分析就要靠人工对清单，容易漏。在系统里标记，才能在 Claim、报表与评估中自动排除 | A：2 人日，**需要 ADR**（Consumer 或绑定加入人设字段及各处的排除规则）<br>B：0 |
| **D6** | 排在什么时候 | **A. v0.1 验收之后（S6）**<br>B. 提前到 v0.1 期间 | **A** | v0.1 的验收对象是现有的 WebChat 路径。期间再引入新的入口，会扩大验收范围，也会增加试运行的变量。Codex 测试已经可以用第 1 期 | A：合计约 13–15 人日（见开头），排入 S6<br>B：同样的工作量，但会挤占 v0.1 收尾 |
| **D7** | 访问别人的或不存在的会话，返回 403 还是 404 | **A. 统一返回 404**，不泄露资源是否存在<br>B. 维持现状：WebChat 对别人的会话可能返回 403 或 409 | **A** | 返回码不同会泄露“这个 ID 存在、只是不归你”。渠道 API 是给程序用的，更容易被拿来枚举 | A：1 人日（渠道 API 加上 WebChat 同步改成 404，并改相关测试）<br>B：0 |
