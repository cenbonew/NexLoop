# 工作台使用说明（负责人）：世界模型、运营人设与外联

- **适用**：v0.1.0 之后第一批、第二批新增的工作台页面（集成分支 `cbd41f57`）。
- **写法**：只用角色名；不含截图、凭据或地址。
- **页面文字**：引号中的文字就是页面上显示的原文。
- **角色**：
  - **负责人**：工作台的 owner 角色；
  - **运营**：operator 角色；
  - **审核员**：reviewer 角色。

  角色清单见 `deploy/authorization/workbench-roles.v1.json`（manifest v18）。

## 1. 世界模型相关页面

导航分组：“模型与资产”下有“企业世界模型”“数据资产”和知识工作台；“管理”下有“能力目录”。

### 1.1 企业世界模型（含“对象”）

- **能看到什么**：已发布的对象、关系、事件、Action 与 Function，全部只读。
  - 标签页：Object Type、Property、Link、事件类型、Action、Function、实例。
  - 顶部“模型计数”一栏里有“实例（real）”的数量。
  - Object Type 与 Link 两个标签页可以在“表格”和“关系图”两种视图之间切换。
- **“对象”就是“实例”标签页**：
  1. 先选“对象类型”；
  2. 列表只显示：对象、Schema 版本、修订、更新时间；用“上一页 / 下一页”翻页，每页最多 100 条；
  3. 点开一个对象，可以看到它“深度 1”的邻域，即直接关联的对象；**属性内容不在这一页显示**。
- **权限**：负责人和运营可以打开。逐个对象的读取权限按角色计算；你没有读取权限的对象只计数，页面上显示为“本页不可见 N 个”。审核员没有因此获得新的读取权限。
- **常见问题**：
  - **为什么有的属性只显示名字？** 它们属于负责人限制的属性组，页面上只显示名称，不显示内容。
  - **对象打不开，提示“对象已不存在”？** 对象已经被删除，例如按删除流程删除了某个客户。
  - **怎么修改模型？** 这个页面不能改。模型变更要经知识工作台审核，再以可信配置发布。

### 1.2 能力目录

- **能看到什么**：系统能做什么、能触达到哪里，全部只读。
  - “受治理能力”：能力、操作、谁可以执行、来源任务、登记时间；
  - “业务 Action”：版本、状态、效应类别、副作用、效应清单；
  - “来信渠道”与“交付路由”；
  - “真实派发”：三层开关当前的状态。
- **权限**：负责人和运营。
- **常见问题**：
  - **这里能开关真实派发吗？** 不能。页面写明了开关“只能由负责人在 设置与治理 中开启或关闭”。
  - **页面提示“真实派发开关暂不可读”？** 后端暂时读不到开关状态。这不代表开关已经打开；稍后刷新即可。

### 1.3 数据资产（含“产物”）

- **能看到什么**：只有计数和时间，不含任何消息原文。
  - “Claim 与提取”；
  - “召回索引”，包括回填记录；
  - “Embedding 预算”；
  - “合并配置”；
  - **产物（Artifact）**：只显示元数据——用途、类型、大小、创建时间、保留期限、所属客户，以及总数；按游标翻页，每页最多 100 条。**每列出一条 Artifact 都会记入读取审计**，所以不要用这个页面做大批量浏览。
- **权限**：产物只有负责人和运营能看。
- **常见问题**：
  - **某一项显示“后端尚未提供这一项；这不表示数量为零”？** 这项指标还没有实现，不代表数量是 0。
  - **“Embedding 预算”一直显示“不可用”？** 目前就是这样。模型预算的实际用量，在“设置与治理”和告警中查看。

## 2. 运营人设与联系偏好

页面：“管理”分组下的“运营人设”。有四个标签页：“人设与版本”“分配”“AI 身份披露”“外联控制”（外联控制见 §3）。

### 2.1 设置人设

1. **建立或发布一个版本**（在“人设与版本”标签页）。要填的字段：人设标识、名字、署名、自我介绍、语气、价值观、单条消息字数上限、表情、用词与称呼、禁用说法、语言、适用场景与不适用场景、“表明 AI 身份时的话术”“被问到是否 AI 时的回避话术”，以及发布原因。
   - 版本一经发布**不能修改**，要改就发布一个新版本。
   - 旧版本可以“停用”或“重新启用”。
   - Agent 不能修改人设。
2. **分配**（在“分配”标签页）。优先级从高到低是：单个客户指定 → 分群规则 → 租户默认。
3. **权限**：发布、分配、发布分群规则、设置 AI 身份披露，都只能由负责人执行，每次修改都有记录。其他成员只能只读查看人设配置。

### 2.2 AI 身份披露（负责人已定的规则）

- **默认不主动表明**是 AI：“主动表明”的默认值是“不主动表明”。可选的还有“首次接触时表明一次”和“每次会话开始时表明”。
- **被直接问到是否是 AI 时**（“被直接询问是否 AI 时”）：默认“用人设里的回避话术回答（话术为空时转人工）”，也可以设为直接“转人工”。
- **能不能自称是人类**：由租户开关“拦截‘自称人类’的说法”决定，默认关闭。打开后，系统会拦截消息里自称人类的说法。
- 还可以选择是否在消息上加“AI 生成”标识。
- 页面上的提示：是否让消费者知道是 AI 由使用方决定；不同法域对 AI 生成内容的标识有不同要求，合规责任由使用方承担。

### 2.3 联系偏好

- **来源**：只来自客户本人的表达，例如客户说“晚上别联系我”。负责人**不能替客户新增偏好**，只能对某条偏好选择“不采纳”。
- **作用**：
  - 时段、频率、渠道、主题四类偏好在**派发时**强制执行，只会让规则比租户规则更严，不会更松；
  - 语气偏好只供对话参考。
- **权限**：只有负责人能查看，也只有负责人能“不采纳”。

## 3. 外联控制

页面：“运营人设”的“外联控制”标签页。修改都经负责人专属的受治理 Action，页面上会显示修订号和“外联控制修改记录”。

> **目前不会真实外发。** 页面上写着“目前还没有外发功能”。负责真正发送的 Action 由外联切片 4 提供，现在还没有发布，所以派发预演中的“真实派发”这道闸门一定是关闭的。即使将来切片 4 上线，真实派发开关也**默认关闭**，打开要由负责人另行决定，并在“设置与治理”中操作。这里的设置现在只用于派发预演。

### 3.1 控制项

| 控制项 | 说明 |
|---|---|
| 时区 | 勿扰时段和频率按这个时区计算 |
| 勿扰时段 | 先勾选“设置勿扰时段”，再填起止时间；可以跨午夜，例如 22:00–08:00 |
| 频率上限 | “每位客户 24 小时最多”与“7 天最多”各一个上限 |
| 开启营销 | 默认关闭 |
| 营销同意模式 | “默认可发，客户表示不同意即停（opt-out）”或“只发给明确同意的客户（opt-in）”。**打开营销时必须勾选确认**：“我确认营销同意模式为「…」，并知悉合规责任由使用方承担” |
| 营销额度 | “7 天最多”，不能超过上面的 7 天上限 |
| 退订话术 | 追加在每条营销消息的末尾，最多 200 字 |
| 发送方标识 | 可选，最多 40 字 |
| 原因 | 每次修改都必须填写 |

### 3.2 外联目的

- 目的说明一次外联“为什么联系”，例如承诺跟进（commitment_followup）、服务跟进（service_followup）。目的的清单是可信配置（`deploy/configuration/outreach-purposes.v1.json`）。
- 负责人可以逐个**启用或停用**目的。没有启用的目的，在预演里会被“目的”这道闸门拦下。
- 要新增一种目的，就要发布新版本的目的清单，这不在工作台里操作。

### 3.3 派发预演

- **作用**：预演列出外联候选，并对每个候选逐道闸门给出结论，回答“如果现在发，会不会被放行、卡在哪一道”。它只读，不发送任何东西。
- **闸门**，按检查顺序：
  1. 暂停（`control_paused`）
  2. 联系限制（`contact_restricted`）
  3. 目的（`purpose`）
  4. 人设排除（`persona_excluded`）
  5. 勿扰时段（`quiet_hours`）
  6. 频率（`frequency`）
  7. 客户联系偏好（`consumer_preference`）
  8. 真实派发（`real_dispatch`）：目前一定关闭
  9. 预算（`budget`）
- **怎么看**：目前**工作台还没有预演页面**，只有负责人专属的只读接口 `GET /api/v1/workbench/outreach-candidates`，需要负责人的工作台会话。页面会在后续切片补上。

## 4. 退订

- **退订词表 v1**（`deploy/configuration/unsubscribe-rules.v1.json`）已由负责人于 2026-10-20 批准。
- **生效范围**：只有在客户最近收到的一条主动消息是**营销**消息，而且在 **30 天内**时，客户回复中的退订词才算退订；命中后只记一条营销主题的拒绝，不会变成全面的联系限制。
- **和拒绝规则的关系**：已有的拒绝规则（`contact-refusal-rules.v1`）**先生效，而且更严**。例如客户回复“退订”，会先按拒绝规则建立联系限制，停止**所有**主动联系，而不只是营销。要改成只停营销，需要负责人决定拒绝规则 v2。
- **当前状态**：截至集成分支 `cbd41f57`，还没有迁移或代码加载这份词表，它还没有实际生效。在它生效之前，所有退订都按拒绝规则处理，也就是更严的那一种。
