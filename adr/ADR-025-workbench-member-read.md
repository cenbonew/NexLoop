# ADR-025｜工作台成员读取消息原文与客户资料

状态：**采用**（负责人 2026-10-10 确认，原话“同意，按你的推荐”）。

关联：ADR-020 §1（Source 对已受理消息的读权限由受治理事实派生）、NX-048（按用途的 message_read_rules）、NX-028 设计稿 D1/D2（企业成员身份与 owner/operator/reviewer 角色）、AT-003（无 READ 时字段与原文不可见）、AT-044（人工接管）。

## 1. 背景

NX-028 切片 1 加入了工作台企业成员（浏览器 Human 会话，独立的 `workbench` 业务应用）。但 SQL 读断言（0011 `nexloop_fact_coverage`，经 `assert_read_authority` 调用）只接受服务主体和 Agent 的事实集；浏览器 Human 的事实是 `browser_authentication`，所以即使给员工配置了 Message READ，读断言也不通过。结果是工作台里所有消息正文、承诺原文和 Consumer 属性都显示“需授权”。

这是失败关闭，不会泄露。但员工接管会话时看不到客户说了什么，人工接管（AT-044）因此无法使用，负责人也看不到承诺原文和客户资料。

## 2. 决定

1. **新增浏览器 Human 的读断言路径，只对工作台成员开放。** 采用“改名保留 + 新包装”：原函数逻辑不变，新包装只在调用方是工作台业务应用的 Human 会话、并且是有效企业成员时，才走新的覆盖判定。顾客会话、服务主体、Agent、Run 凭据的判定一律不变。
2. **按角色派生，不逐对象授权：**
   - **owner、operator**：本租户、本 world 内所有会话的 Message 正文，以及 Consumer 属性。负责人在 `owner-property-restrictions.json` 中标为受限的属性组，同样不开放。
   - **reviewer**：只读取当前待审核条目（Claim 或候选定义）引用的证据消息，审核结束后失效。
   - 派生在 SQL 中于每次读取时计算。成员资格被撤销、角色变更、会话吊销后，下一次请求即失效。
3. **每次读取都留审计。** 新增只追加的读取审计记录，字段包括：成员主体、角色、读取对象（会话、消息或 Consumer）、读取用途（页面或动词）、时间。审计写入失败时，本次读取一并失败。审计记录只开放给 owner 和审计角色读取。
4. **不放宽其他边界。** 写入仍然只能通过受治理的人类 Action；工作台成员不能借此获得任何服务或 Agent 权限；顾客主体与企业成员互斥（0116 的触发器）保持不变。

## 3. 后果与测试

- AT-003 的正例（有 READ 时可见）由此成立，反例（无 READ 或被撤销时不可见）继续成立。
- 至少覆盖以下测试：
  - owner 和 operator 能读本租户、本 world 的消息与 Consumer 属性，读不到其他租户或 world 的；
  - reviewer 只能读待审核条目的证据，审核结束后读不到；
  - 撤销成员资格或角色后，下一次请求即被拒；
  - 负责人标为受限的属性组读不到；
  - 顾客会话、服务、Agent、Run 凭据的读取结果与改动前完全一致（回归）；
  - 每次读取都有一条审计记录，审计写入失败时读取也失败；
  - 非 owner 读不到审计记录。
- 实现由 NX-028 切片 1 的后续完成（L2 线）。
