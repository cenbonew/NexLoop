# ADR-034｜测试人设在系统内标记（persona）

状态：**proposed**（提议，待批准）。来源：负责人 2026-10-17 对消费者通道 API 第 2 期的拍板，D5 =“系统内 persona 标记”。按 D6，实施放在 v0.1 之后，排入 S6。编号为临时编号，合入时由调度员确认。

关联：[消费者通道 API 设计稿](../docs/design/consumer-channel-api.md)；[拍板单](../docs/design/consumer-channel-api-decisions.md)；ADR-033（渠道代表消费者执行）；NX-037 参与者变更（负责人 2026-10-14：客户由 AI 代理扮演，证据中标为 `persona: simulated_agent`）。

## 1. 背景

v0.1 的受控试运行由 AI 代理扮演顾客。现在测试人设**只在证据里**区分：交互记录与证据包中的 `persona`，以及 participants 清单。系统内（数据库、工作台、导出、Claim 与记忆）没有任何标记，这一点验收报告模板已列为限制。后续分析要排除这些账号，只能按清单人工核对。

第 2 期开放渠道 API 之后，Codex 等测试驱动会长期产生测试流量。这些流量如果和真实客户的数据混在一起，会污染 Claim、记忆、评估语料与经营报表。

## 2. 决定

1. **persona 作为消费者的受治理属性**：新增受治理 Action `nexloop.consumer.set_persona`，执行者是负责人，取值为 `real`（默认）、`simulated_agent`、`synthetic`。它带修订号与审计，只能经这个 Action 修改，不能经由任何业务对象编辑间接改变。
   - **为什么放在消费者上，而不放在消息上**：人设是“这个客户是谁”的事实，不随单条消息变化；放在消费者上，下游各处只需要按消费者判断一次。
2. **渠道绑定**（ADR-033）上也带 `persona`。规则：经测试渠道绑定的消费者，persona 不能是 `real`；绑定时如果消费者的 persona 是 `real`，拒绝绑定。这样可以防止测试渠道误用真实客户。
3. **下游按 persona 排除**：
   - **Claim 与记忆**：非 `real` 消费者的 Claim 照常提取（便于测试提取器），但都带上 persona，默认不进入跨消费者的聚合，也不进入评估语料；
   - **报表与导出**：经营数据与 metrics 视图默认排除非 `real` 消费者，另提供一个包含它们的版本，按 persona 分列；
   - **工作台**：员工页的会话与客户显示人设标签，例如“测试 / 模拟”，避免员工把测试会话当作真实客户；
   - **证据包**：participants 中的 persona 改为从系统读取，与证据中的标记一致。
4. **不影响受治理路径**：persona 不改变授权、联系限制、回复保证、预算或真实派发开关。测试消费者同样受全部约束，这样测试才有意义。

## 3. 后果

- **优点**：测试流量可以在系统内被自动排除，不再依赖人工清单；工作台可见；与证据中的标记一致。
- **契约改动**：
  - Consumer 对象增加 `persona` 属性，按新版本对象类型发布；
  - 新增一个 Action；
  - metrics 与导出视图增加 persona 过滤。
  - 以上都按“新迁移 + 新版本”实施，不改已发布的迁移。
- **存量数据**：v0.1 试运行中的测试账号（`customer-1`…`customer-4`、`refusal-1`、`refusal-2`）在实施时由负责人用新 Action 补标为 `simulated_agent`，补标留审计。没有标记的消费者都视为 `real`。
- **风险**：
  - 有人把真实客户误标为测试人设，导致其数据被排除出分析。缓解：只有负责人能执行这个 Action，并且每次修改都留审计；
  - 反过来，测试客户忘了标记。缓解：经测试渠道绑定时强制检查（决定第 2 条）。

## 4. 不做

- 不按 persona 放宽任何安全或治理约束。
- 不删除测试人设的数据。删除仍走 NX-029 的流程。

## 5. 测试（实施时）

- 设置与修改 persona 只能经该 Action，有修订号与审计；其他路径修改会被拒绝。
- 测试渠道绑定 persona 为 `real` 的消费者时被拒。
- metrics 与导出视图默认排除非 `real` 消费者，带 persona 参数时按人设分列。
- 非 `real` 消费者的 Claim 带 persona，并且不进入聚合与评估语料。
- persona 不影响授权、联系限制、回复保证与预算：同一条消息，在 persona 为 `real` 与 `simulated_agent` 时，受治理路径的结果相同。

## 6. 回滚

停止使用这个 Action，各下游过滤恢复为“不排除”。已写入的 persona 属性保留（只追加）。
