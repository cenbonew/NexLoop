# ADR-029｜guard 在同一 Run 的多次授权间复用 Source 签名的上下文信封

状态：**提议**（草稿，待负责人裁定）。调查分支 `guard-envelope-reuse`（自 main b1b3418），本草稿不含实现。

关联：AGENTS.md“派发时按当前权限复查”；ADR-022 §4（guard 单次调用 2 s 时限）；ADR-024（guard 多进程）；ADR-027、ADR-028；调度员 2026-10-12 对 guard-authz-memo 的约束（备忘只限一次授权或同一事务，不跨请求）——本 ADR 提议对**签名信封**放宽这条约束，因此需要负责人裁定。

## 1. 背景

AT-060 阶梯在 CI 主机上正确性已干净（100/200 客户 0 失败），瓶颈是吞吐：历史回复约 0.2/s，外推 1000 客户需 2.4–2.9 h。目标是翻倍到 ≥0.4/s。

实测（本机，main a58c42b + history-monitor）：

- 200 客户模板，pg_stat_statements：每次 guard 授权的 SQL（`nexloop_runtime_activation_command`）平均约 36 ms，约 4150 条嵌套语句；最重的是权威事实主键查询（每次授权约 295 + 197 次，单次约 0.06 ms）、grants 存在性检查、凭据与身份相关读取。单条都很便宜，代价来自次数。
- 但 history-monitor 读到的 guard 每次授权 p50 约 170 ms（100 客户），远大于 36 ms 的 SQL。cProfile（一次 model 授权，单进程无并发）：**每次约 214 ms，其中约 146 ms（68%）在构建服务目录信封**（`_context_catalog_envelope` → `service_offerings` → `object_reads` → 事实解析，每次授权 2 次），其余主要是角色、关系与正式读取信封和事实规范化（`facts._canonical_value`，每次授权约 4 万次递归调用、约 57 ms 纯 CPU）。
- 这些信封由 Source 身份签名、带不超过约 25 s 的有效期；SQL 在每次使用时按**当前**权威数据重新校验（记录摘要、目录摘要、授权事实）。目前同一信封只在一次 guard 工具请求内复用（`scoped_envelope`），跨授权每次都重建。

## 2. 提议的决定

1. guard 进程对**同一 Run** 的 Source 签名上下文信封（服务目录、角色、关系、正式读取）做进程内复用：键为（Run 的来源摘要、上下文定义的规范摘要、信封种类），只在信封自身签名的有效期内复用，并留出安全余量（例如剩余有效期 < 5 s 即重建）。
2. **SQL 的每次使用校验完全不变**：复用的只是“由 Python 构建并签名的证明”，SQL 照旧按当前事实、记录摘要与目录摘要验证；只要权威、对象或目录有任何变化，校验失败，guard 丢弃缓存并现场重建一次再授权；重建后仍失败才拒绝。
3. 缓存只在内存中、只按 Run 维度、有条目上限，进程重启即清空；从不跨 Run、跨租户或跨 world 共享；不缓存任何拒绝结果。
4. 不改变任何时限、授权范围、ADR-027/028 的复查组。

## 3. 理由

- 撤销与变更的生效仍取决于 SQL 的每次校验，而不是信封是否新建：信封只是“Source 在某一时刻能读到这些内容”的签名证明，SQL 校验它在**当前**是否仍成立。复用一个仍在有效期内、且当前仍校验通过的证明，与现场新建一个内容相同的证明，在授权结果上等价。
- 风险在于：如果某项变化不体现在 SQL 校验的摘要里，复用会让旧证明多存活至多一个有效期（≤25 s）。实现前须逐一核对四类信封的 SQL 校验覆盖面，并以测试证明撤销、对象修订、目录变化、限制生效都会让复用的信封立即被拒。

## 4. 后果与验证

- 预期：每次授权的 Python 侧耗时从约 214 ms 降到约 70 ms 以下（只省去信封重建），按 guard 为瓶颈估算吞吐提升约 2 倍；以 200 客户模板 + history-monitor 实测为准，再到 CI 主机复测。
- 测试须覆盖：缓存命中时 SQL 仍逐次校验；权威撤销、对象/目录修订、联系限制、Run 凭据撤销后，下一次授权拒绝或重建（不得沿用旧证明通过）；有效期临近时重建；不同 Run 之间不共享。
- 另一项同语义的纯 CPU 优化（事实规范化，约 57 ms/次）在 vendored 的 EIOS 内核 `eios/authz/facts.py`，可以对冻结模型的规范摘要做实例级缓存或改写递归；它不改语义，但会扩大与上游的差异，单独提交、记录到 PROVENANCE。
- 被拒绝：直接加大 guard 进程数或连接池（受连接预算 60 的限制，且不解决单次授权的成本）；跨 Run 共享信封。
