# ADR-041｜企业自有 Agent / 程序的机器接入通道（F1–F3）

状态：**草案**（2026-10-28；L6 复核 6950f93f 判 PASS，重要项 I1 与建议 S1–S4 已补入，见威胁评审 §10；待负责人拍板 §6）。来源：负责人 2026-10-22 Q3 按推荐 A（方向确定，S7 之后实施，先做 C8）；负责人 2026-10-28 决定提前做威胁评审与 ADR，只写文档，不写代码，不开放任何接口。实施任务：NX-062。

## 1. 背景

NexLoop 今天的程序化入口只有三种：Pi Run 的短期服务令牌、消费者渠道（ADR-033）和 test 模式下的 Artifact 读取。企业自己的程序或 Agent 没有入口，只能模拟人登录工作台，这既违反“不伪造人类身份”，也没有审计归属。

上游 EIOS 有 API key、MCP server 与 Agent 网关（`access_admin.py`、`api/access.py`、`mcp/server.py`、`agent_gateway/*`），但迁移 0313–0326 与领域耦合，只能取语义：API key 走平行许可链、实例写只经受治理 Action、没有审批决定工具、需要二次确认、scope 取合取、网关拒绝伪造的身份头。

## 2. 决定

1. **机器主体**：企业程序在租户下登记为服务主体（类型 `machine_client`），带用途说明。登记、停用只能经受治理 Action，执行者为负责人（Q-4）。机器主体不代表任何人，不做委托（Q5、ADR-033）。
2. **机器密钥**：
   - Bearer 令牌，带固定前缀以区别于 Run 令牌与渠道凭据；明文只在签发时出现一次，服务端只存 HMAC-SHA256 摘要（服务端密钥来自私有配置）与非秘密的前缀 ID；
   - 每把密钥绑定一个租户、一个 world；必须有有效期（上限见 Q-2）；每个主体最多两把有效密钥，用于轮换重叠；
   - 签发、轮换、吊销是受治理 Action，执行者为负责人；吊销立即生效，每次请求按当前事实检查，不缓存“有效”结论（T-1、T-2）；
   - 机器主体停用时，它名下全部密钥在同一事务里级联吊销；认证同时要求密钥有效且主体启用，重新启用主体不会让旧密钥复活（T-2）；
   - 摘要用的服务端 HMAC pepper 支持双版本轮换（密钥记录 pepper 版本，过渡期内新旧并存），并纳入私有备份；pepper 丢失即全部机器密钥失效，恢复演练覆盖这一项（T-1）；
   - 异常检测（拒绝率等）的阈值写进告警规则的新版本，不写死在代码里（T-1）。
3. **授权是合取，在派发时检查**：一次机器调用要同时满足密钥 scope、机器主体的服务授权、能力当前的策略（含 NX-056 审批）。三者都在 PG 的受治理入口按当前事实检查；网关与应用层的检查只是提前拒绝，不是最终判定（T-3）。
4. **入口面由 C8 清单锁定**：
   - C8 清单新增 realm `machine_key`，只能用于逐条登记的路由；G-2 的精确集合、G-5 的拒绝探测同样适用，并扩展为“每条路由 × 每种凭据”的期望拒绝码；
   - realm 互斥：机器密钥在其他 realm 的路由上一律 401，其他凭据在 `machine_key` 路由上一律 401；
   - 机器路由按能力逐条登记，不开放工作台写入口的通用分发；
   - 以下能力**永不**授予机器主体：审批决定；密钥、服务授权、成员与角色管理；各类发布（Schema、策略、规则、关系类型）；擦除与保留决定；真实派发开关；补救的人工决定。清单检查与 SQL 双重锁定。
5. **请求形状**：
   - 租户、world、actor 只从凭据推出，请求中出现这些字段返回 422；应用不读身份类请求头，Gateway 删除它们（T-5）；
   - 每个机器可调用的能力都有参数 Schema，未知字段拒绝；对象 ID 必须在调用方可见范围内，否则 404，不区分“不存在”与“不可见”（T-4、T-11）；
   - **读取的字段投影**：机器读取默认不返回会话正文、消息正文和联系方式；每个机器可用的读取动词按能力逐条登记返回字段，未登记的字段不返回，投影在 SQL 读取函数里执行；需要正文或联系方式时由负责人按能力逐条决定（Q-9）。机器读取遵守擦除与保留状态，与 NX-054 的统一擦除判定及工作台读取一致，不另写判定（T-12）；
   - 写请求必须带业务意图 ID；同一主体同一意图 ID：内容相同返回首次结果，不同返回 409；先持久化后 ACK；unknown 结果返回 unknown 与查询入口（T-6）。
6. **模型输出不直接成为动作（Q7 的吸收部分）**：
   - 有副作用的 Action 分 `prepare` 与 `commit` 两步，`commit` 必须带回 `prepare` 返回的规范化参数摘要（T-4）；
   - 外部效应能力只在第二期开放，并且必须配置审批策略；机器主体只能是请求人，不能是审批人，也不计入法定人数（Q-1、Q-6）；
   - 联系限制、频率上限、真实派发开关在派发时照常检查，机器路径不另开。
7. **限速与预算**：按密钥与按租户两级限速，持久在 PG，键由服务端绑定（不以客户端 IP 为唯一键）；按密钥的日动作预算；超出返回 429 与 `Retry-After`；机器路由有独立并发上限（T-8）。
8. **审计**：actor 为机器主体，另记密钥前缀 ID、意图 ID、trace_id、能力与结果码；不记密钥与正文。写入 `runtime.audit_events`，因此进入 NX-059 哈希链；密钥生命周期事件同样进链（T-9）。
9. **客户端（MCP、SDK、CLI、技能包）只是 HTTP API 的客户端**：
   - MCP 只做本地 stdio 客户端，工具集合等于密钥 scope 内的 `machine_key` 路由，不提供审批与密钥管理工具（Q-5）；
   - 密钥只从私有文件（0600、本人所有）或环境变量引用读取，不接受命令行参数，不打印；
   - 地址与 CA 都是配置项，不写死任何部署地址；
   - SDK 遇到 unknown 默认查询，不重发（T-1、T-6、T-10）。

## 3. 备选方案

| # | 方案 | 不选的理由 |
|---|---|---|
| A | **采用本 ADR**：机器服务主体 + 合取 scope + C8 `machine_key` 精确集合 + 分期开放 | — |
| B | 复用 EIOS 委托凭据，让程序“代表负责人”执行 | 需要伪造人类会话（违反硬约束）；与 ADR-033、Q5 冲突；审计归属到人，事后无法区分 |
| C | 让程序用负责人或员工的工作台账号登录（cookie 会话） | 伪造人类身份；无法限 scope；口令落到程序配置里；审计不可区分 |
| D | 移植上游独立 Agent 网关进程，在网关做授权 | 多一个授权判定点，与“派发时在 PG 按当前事实检查”重复且可能不一致；多一个需要运维的进程 |
| E | 托管远程 MCP 服务（服务端直接暴露 MCP） | 新的长连接协议面，需要另做会话、限速与清单；本地 stdio 客户端经 HTTP API 已能满足，并自动受 C8 与 G-5 约束 |
| F | 一期就开放外部效应能力，只靠 scope 控制 | 模型输出驱动外部效应的风险（Q7）在没有审批与两步确认时无法接受 |
| G | 用请求签名（HMAC + 时间戳 + nonce）代替 Bearer | 抗重放更强，但客户端实现成本高、调试难；幂等键已覆盖重复执行；作为第二期选项（Q-3） |

## 4. 后果

- **优点**：
  - 企业程序有了正当身份，审计可区分人、Pi Run、渠道与企业程序；
  - 入口面由 C8 清单与发布门锁定，新增机器路由必须审查，漏检会让发布失败；
  - 吊销、过期、限速与预算把密钥泄露的损害限制在可控窗口内；
  - 第一期不碰外部效应，风险最高的部分推迟到审批与两步确认就绪之后。
- **契约与数据改动（实施时，按“新迁移 + 新契约版本”）**：
  - 主体类型 `machine_client`、机器密钥表（摘要、前缀、租户、world、有效期、状态）、密钥 scope；
  - 受治理 Action：机器主体登记与停用、密钥签发、轮换、吊销；
  - C8 清单 Schema 增加 realm `machine_key`，以及机器读取动词的字段投影；
  - 受治理入口的授权函数增加“机器密钥 scope”分支；
  - 意图 ID 去重表（或复用现有业务意图 ID 的存储）；
  - 限速与预算表；
  - 不改已发布的迁移，校验和不变。
- **代价**：
  - 每个机器可调用的能力都要补参数 Schema 和 `prepare`/`commit`；
  - G-5 探测的矩阵变大（路由 × 凭据种类）；
  - 工作台新增密钥管理页面；
  - 工作量按差距分析估计 F1 约 20 天，加 F2 约 5 天、F3 约 2 天。
- **风险**：见威胁评审 §6（R-1 至 R-4）。

## 5. 不做

- 委托、紧急提权（Q5、ADR-033）；
- 托管远程 MCP 服务、独立 Agent 网关进程；
- 出站 webhook；
- 工作台写入口的通用分发；
- 机器主体创建消费者、成员或其他主体；
- OAuth 第三方授权。

## 6. 需要负责人拍板的问题

| # | 问题 | 选项 | 推荐 | 理由 |
|---|---|---|---|---|
| Q-1 | 第一期开放范围 | A. 只读动词 + 无外部效应的受治理 Action；外部效应放第二期并强制审批<br>B. 一期全部开放，靠 scope 控制<br>C. 一期只读 | **A** | 外部效应不可撤回，且有模型输出驱动的风险；只读太窄，企业 Agent 无法完成登记、更新类工作 |
| Q-2 | 密钥有效期与轮换重叠 | A. 有效期上限 90 天，重叠上限 7 天<br>B. 上限 365 天<br>C. 不设上限 | **A** | 泄露窗口有限；90 天是常见的企业密钥轮换周期 |
| Q-3 | 认证方式 | A. 一期 Bearer + TLS + 幂等键，二期再评请求签名<br>B. 一期就要求 HMAC 请求签名 | **A** | 幂等键已防重复执行；签名提高客户端门槛，等有真实企业接入再评 |
| Q-4 | 谁能签发、吊销密钥 | A. 只有负责人<br>B. 负责人与持有专门授权的员工 | **A** | 签发密钥等于授出权限，与现有“授权由负责人决定”一致；需要时再经审批策略放开 |
| Q-5 | MCP 形态 | A. 只做本地 stdio 客户端（经 HTTP API）<br>B. 同时做托管远程 MCP 服务 | **A** | 不新增协议面；自动受 C8 与 G-5 约束 |
| Q-6 | 机器主体在审批中的角色 | A. 只能是请求人，不能是审批人，不计入法定人数<br>B. 可以是审批人 | **A** | 审批的意义是由人把关；机器自批等于没有审批 |
| Q-7 | 密钥与 world | A. 每把密钥绑定一个 world；stage 上允许 test world 密钥用于演练<br>B. 一把密钥可跨 world | **A** | 与 Run 的 world 规则一致；防止 sim/test 调到 real |
| Q-8 | 来源网段白名单 | A. 每把密钥可选，默认关<br>B. 强制必填<br>C. 不提供 | **A** | 企业出口地址不总是固定；可选能在有固定出口时多一层防护 |
| Q-9 | 机器读取能否返回会话正文与联系方式 | A. 默认不返回；需要时由负责人按能力逐条加入字段投影，留审计<br>B. 按 scope 整体放开<br>C. 永不返回 | **A** | 个人数据是最大的泄露面（T-12）；逐条决定既能满足确有需要的场景，又让每一处放开都可审查；永不返回会挡住客服类企业 Agent 的正当需求 |

## 7. 测试（实施时）

见威胁评审 §8 的测试清单。验收至少包括：

- 每条路由 × 每种凭据的期望拒绝码（G-5 扩展），在真实 PG 上运行；矩阵为空或行数不等于“路由数 × 凭据种类数”时门禁失败，不能静默通过；
- 密钥生命周期：只显示一次、摘要存储、过期与吊销立即生效、两把上限、world 绑定、主体停用级联、pepper 轮换；
- 读取：返回字段等于登记的投影，默认无正文与联系方式；擦除、保留状态下与工作台读取结果一致（T-12）；
- 写入：身份字段 422、他人对象 404、幂等 409、两步摘要 409、外部效应能力无审批策略时拒绝；
- 审计：actor 与密钥前缀正确，进入哈希链并通过带密钥校验，没有密钥与正文；
- 客户端：不打印密钥；unknown 时查询而不重发；MCP 工具集合等于 scope。
